# 后台任务与 Word 导出

## 启动与职责

识别、AI 对话和 Word 导出由 pg-boss 调度，Node Worker 执行。Nuxt 处理 HTTP 和账号权限，不在提交请求中等待整个模型或文档工作结束。

    npm run worker:setup
    npm run worker

本地 Worker 使用当前项目配置；生产使用独立容器。修改密钥或提供方配置后需要重启 Worker，不能只刷新浏览器。启动前确保数据库、私有存储和所选提供方可用。

[Worker 入口](../server/worker/start.ts)启动消费者和恢复流程；[queue 模块](../server/queue)维护队列和执行权；具体识别、聊天、导出实现在 server/worker 下。用户页面读取业务任务，不依赖直接访问队列表。

## 幂等、额度与重试

账号和 requestKey 标识一次提交，相同内容可确认旧结果，改变内容返回冲突。项目额度与入队在同一事务中提交。默认每天识别 50、对话 30、导出 20，按 UTC 日期计算（北京时间 08:00 切换），可配置。

| 操作         | 业务语义                                         |
| ------------ | ------------------------------------------------ |
| 回执确认     | 同一意图、原请求键，不创建新任务或重复扣项目额度 |
| 队列自动重试 | 同一任务的新尝试，仍受执行权保护                 |
| 用户重新生成 | 明确的新轮次，使用新项目额度                     |

Worker 在处理前、进度提交和最终落账时校验当前 claim。业务结果与队列完成必须一起提交，旧进程不能在租约失效后覆盖新执行者。外部 AI 调用不在数据库事务里，响应丢失仍可能导致供应商计费不确定；项目内幂等不能承诺外部 exactly-once。

停止任务和 Worker 退出后的恢复规则见[失败恢复](FAILURE_RECOVERY.md)。不要手动改数据库状态来模拟成功，也不要同时启动多份未评估的消费者扩大模型并发。

## 对话进度

SSE 返回持久化会话快照，带版本和轮次信息，前端拒绝旧快照；断线时有限重连及轮询补读。停止后保留已有文本，失败后可重新生成。只有完整成功问答进入后续模型上下文。

结构化解释先校验输出结构再保存，历史会话绑定内部公式内容，因此修改公式不会偷偷改变旧解释的输入。内部 FormulaVersion 不对应面向用户的版本选择器。

## 导出与 Pandoc

先安装 Pandoc 或配置 PANDOC_PATH；项目可能使用本机便携安装，但该工具目录不随 Git 克隆。生产镜像包含发布所需转换工具。

提交导出时指定 formulaVersionId、requestKey，后台绑定该内容生成 DOCX 并写入私有存储。成功后通过账号 API 下载，不能绕过归属直接读取对象地址。导出使用原生 Word 数学对象，支持编辑；Word/WPS 的实际排版须使用目标客户端验证。

    npm run test:documents

此检查验证文档生成，不替代目标客户端的人工检查，也不证明真实模型输出正确。

## 故障排查

| 现象           | 查看位置                                         |
| -------------- | ------------------------------------------------ |
| 任务一直排队   | Worker 是否运行、队列是否初始化、数据库连接      |
| 多次尝试后失败 | 任务错误码、Worker 日志、供应商/识别服务与 trace |
| 页面暂时没更新 | 读请求、SSE、快照版本与网络；不要重复提交        |
| 导出失败       | Pandoc 路径/退出状态、公式输入、私有存储         |
| 成功但下载失败 | 当前账号、导出引用与文件状态                     |
| 同键冲突       | 是否错误复用了另一请求的 requestKey              |

先到[自动错误中心与链路查询](OBSERVABILITY.md)定位同一任务的服务记录，再查看执行权和外部调用。测试须使用[隔离入口](TESTING.md)，不能把生产任务当作故障演练数据。
