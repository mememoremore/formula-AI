# 私有对象存储

## 职责和配置

对象存储保存图片与 DOCX 文件本体，PostgreSQL 保存 owner、对象键、状态、引用和资源租约。当前本地及单机方案使用 SeaweedFS 的 S3 兼容接口，不需要 AWS 账号。

    npm run storage:env
    npm run storage:up
    npm run storage:check

配置包含 Endpoint、Region、Bucket 和配套访问凭据。storage:env 补齐本机配置，storage:check 使用签名请求检查桶访问。开发默认回环端口 8333；生产容器通过隔离网络访问 storage:8333，不能把容器内 localhost 当作宿主。端点限制由对象存储适配器控制，不应为适配远程服务而开放任意明文地址。

S3 API 不公开给浏览器；私有图片与下载都经过账号 API。不要把桶改成公开可读来解决预览问题。

## 上传与资源状态

浏览器上传 JPEG/PNG 原始字节，带 x-upload-key、x-file-name 和 Content-Type，不使用 multipart。服务端验证字节限制、图像内容并使用 Sharp 规范化，不能仅相信扩展名。

上传先登记受控租约与资源身份，再执行对象写入，最后确认数据库状态。主要文件状态为 PENDING、READY、DELETING、DELETED。外部 I/O 与数据库提交不能形成单一原子事务，超时后必须区分“确定失败”和“写入结果不明”。

识别任务引用已就绪的本人文件。相同上传键用于确认原操作，不能在响应丢失时生成新键无限上传。已失败任务仍可能引用输入图，因此“任务失败”不等于“图片可删”。

## 租约与受限清理

Worker 有租约恢复和孤立图片核对，详见[失败恢复](FAILURE_RECOVERY.md)。自动孤立图片模式通过 FORMULA_RESOURCE_ORPHAN_MODE 设置：

| 模式   | 行为                               |
| ------ | ---------------------------------- |
| off    | 停用该孤立图片核对                 |
| report | 默认只报告候选项                   |
| apply  | 仅对通过全部条件的孤立图片执行删除 |

apply 是本项目自定义配置值，不是数据库或 Docker 的通用命令。它不授予删除整个存储桶的权限。允许范围限于登记完成的 IMAGE、无引用、无活动或不确定租约，且超过至少 24 小时宽限期。

PENDING、未知对象、头像、导出文件、模型和备份不在该自动清理范围。删除前复查引用并记录审计，删除后 HEAD 确认不存在才落账；无法确认的状态交由进一步核对，不能按文件年龄猜测删除。

本机只读审计：

    npm run storage:audit

单文件执行参数和限制见失败恢复文档。不要把清理模式从 report 改为 apply 作为排障的第一步；先确认配置桶和审计结果。

## 查看、备份与停止

    docker compose ps storage
    docker compose logs --tail 80 storage
    npm run storage:down

停止保留卷。迁移或恢复时数据库与对象数据需要一起规划；只拷贝数据库会留下缺失图片与下载。备份不得进入 Git，生产操作见[部署手册](../deploy/README.md)。

| 现象                 | 检查                                            |
| -------------------- | ----------------------------------------------- |
| 签名或鉴权失败       | 应用与存储凭据、Region、时间、Endpoint 是否对应 |
| 浏览器 404           | 当前账号、文件状态、数据库引用，不直接开放桶    |
| 上传响应丢失         | 原上传键和租约状态，先确认原对象                |
| 对象存在但任务未创建 | 原提交回执、文件是否可引用及清理宽限期          |
| 文件被标记待核对     | 结合生产者是否活跃与审计，不直接删除            |

实现入口：[object-store.ts](../server/storage/object-store.ts)、[资源模块](../server/resources)。
