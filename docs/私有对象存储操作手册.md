# 私有对象存储操作手册

当前本机使用 Docker SeaweedFS 4.48，Nuxt 通过 S3 API 写入。文件元数据保存在 PostgreSQL，图片内容在对象存储命名卷中。

## 启动

先启动 Docker Desktop，在项目根目录执行：

```powershell
npm install
npm run db:env
npm run auth:env
npm run storage:env
npm run db:up
npm run db:migrate
npm run storage:up
npm run storage:check
npm run dev
```

`storage:up` 会先补充空缺配置，再启动存储并等待健康检查。已有数据库密码、认证密钥或非空存储配置不会被覆盖。修改配置后重启 Nuxt。

打开 `http://127.0.0.1:3000/login`，注册后进入上传页面。本次无需注册云厂商或提供付费密钥。

## 私有配置

| 环境变量                       | 默认含义                   |
| ------------------------------ | -------------------------- |
| NUXT_STORAGE_ENDPOINT          | 本机 http://127.0.0.1:8333 |
| NUXT_STORAGE_REGION            | us-east-1，供 SDK 签名使用 |
| NUXT_STORAGE_BUCKET            | formula-private            |
| NUXT_STORAGE_ACCESS_KEY_ID     | 脚本随机生成的访问标识     |
| NUXT_STORAGE_SECRET_ACCESS_KEY | 脚本随机生成的私有密钥     |

真实值只在 `.env` 或部署环境；不要把密钥填进 public runtimeConfig、浏览器代码或文档。生产 Node 服务需要注入环境变量，不自动读取项目 .env。

Docker 容器为 `formula-ai-storage-1`，命名卷为 `formula-ai_storage_data`。只发布本机 8333 端口；未发布的管理端口不要临时开放给公网。容器启动脚本检查密钥非空，避免误启动匿名写入服务。

## 日常操作

```powershell
npm run storage:up
npm run storage:check
docker compose ps
npm run storage:down
```

停止容器不会删除数据。不要执行 `docker compose down -v` 作为日常重启命令。数据卷不是备份，后续部署阶段仍需验证备份恢复。

`storage:check` 通过带签名的 HeadBucket 检查连接，不打印密钥。健康检查只证明本机服务已响应，不代替写入与权限验收。

## 图片状态排查

进入数据库：

```powershell
docker compose exec postgres psql -U formula -d formula_ai
```

只读检查：

```sql
SELECT status, count(*) FROM stored_files GROUP BY status;
SELECT id, "ownerId", name, status, "createdAt"
FROM stored_files
WHERE status = 'PENDING'
ORDER BY "createdAt";
```

- READY：上传与数据库确认成功，可以通过账号接口读取和识别。
- DELETED：上传失败后对象已尽力清理；原请求可以重试。
- PENDING：可能仍在上传，也可能是进程中断或补偿未完成。本次没有定时自动恢复。

不要直接把 PENDING 批量改成 READY，也不要删除全部待处理文件。应结合创建时间、所属用户、对象是否存在和服务日志判断；先确认不是正在上传，再设计单条修复。后续恢复流程需要同时处理对象和数据库状态。

存储或数据库短暂不可用时，页面显示失败。客户端保留重试请求键，已确认成功的文件可以复用，不要求重新选图。关闭页面后临时请求键不会永久保留；长期请求恢复属于后续可靠任务设计。

## 切换兼容云存储

调整 endpoint、region、bucket 和访问密钥，确保 bucket 已创建且匿名访问关闭；使用只允许该业务所需操作的服务账号，再重启 Nuxt 并执行上传、读取和跨用户检查。适配器当前使用 path-style S3 请求，云服务是否兼容需要实际验证。

改配置不会自动搬迁旧图片。旧文件行记录原 bucket 和 objectKey，更换 bucket 或存储服务前需要迁移对象并核对元数据；本次读取适配器使用当前配置的 bucket，不能假称修改配置后历史图片会自动迁移。

Nuxt 运行在宿主机，所以当前 endpoint 使用回环地址；以后 Nuxt 也进入容器时，应改为容器网络中的服务地址并按部署网络配置 HTTPS/访问控制。当前实现只允许回环 HTTP，非回环 endpoint 必须使用 HTTPS。
