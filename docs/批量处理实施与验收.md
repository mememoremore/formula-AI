# 批量处理实施与验收（2026-11-08）

## 使用方式

首页“输入 LaTeX”下方新增“批量处理”。进入后先选“每张都是单公式”或“每张都是多公式”，同一批次统一使用一种模式。每批最多10张 JPEG / PNG 图片，每张不超过10MB、2000万像素。

单公式图片可直接识别，也可调整裁剪。多公式图片逐张检测、勾选和调整裁剪，每张至少2个、最多20个区域；目前沿用原项目上下分行公式的检测能力。上传前可移除图片、调整顺序，切换模式需重新选择图片。

上传完成并创建批次后，后台按原图和区域顺序处理。结果按原图分组，显示逐条状态；可返回首页或刷新，从“批量处理”的最近批次继续查看。提交响应丢失时保留原请求，刷新后点击“继续确认原批次”核对，不另建任务。

成功公式自动进入未分类。勾选成功结果后可复制 LaTeX / 源公式、导出仅含公式的图片版 / 可编辑版 Word，或添加到已有分类。复用现有复制和导出上限，每次最多选择20条，可分次操作。

只重试失败项，成功任务及公式保持原编号。每个公式区域按现有规则占用一次识别额度；重试会按现有规则使用新的识别额度。上传前检查当前剩余额度，创建批次及实际提交子任务时再次检查。若被其他任务用完额度，批次暂停，额度恢复后可继续。

## 核心实现

- 新增批次、原图、区域三张关联表，不重建原表，不修改已有账号、公式或识别记录。
- 复用既有图片上传、识别任务、额度、PgBoss 队列和模型。独立 Worker 每2秒核对未完成批次，每批最多一个未完成子任务，浏览器关闭后仍能继续。
- 数据库租约与条件更新协调调度；每个区域持久保存请求编号，重复提交、调度重启和未知响应均重放原请求。
- 批次接口按登录账号隔离，图片和分类均验证归属；重试带失败任务快照，避免过期操作覆盖新任务。
- 原图和区域文件纳入已有引用检查，防止被遗留图片清理误删。新增引用使用延迟外键检查，兼容账号删除时的多层级联清理。
- 没有新增第三方依赖，没有改动原小程序、模型文件、账号密码或 DeepSeek 密钥。

## 尚未验证与边界

- 未跑全套隔离数据库、CI 或所有端到端测试；没有宣称它们通过。未实际强杀 Worker 进程进行故障注入；调度重放分支有自动测试，关闭页面和 HTTP 响应中断有实际浏览器验证。
- 准备图片及上传阶段依赖当前页面。创建批次后才进入持久后台处理；准备阶段离开会提示重新选择。
- 识别准确率仍由现有模型决定；多公式检测沿用上下分行区域能力，复杂混排需手动处理。
- 每个账号最多同时保留两个进行中或暂停的批次；最近列表显示20批，尚未增加全部批次分页、删除入口或批次文件保留期限。原图与裁剪文件计入现有账号存储限额。
- 新增调度器需随既有 Worker 运行；部署时需先应用迁移并生成 Prisma 客户端。延迟外键检查由 SQL 迁移维护，Prisma 模型不能表达该属性，后续迁移应保留。
- 新增了批次生命周期与文件保留的维护责任；没有新增依赖或对既有服务进行重写。


最终运行状态：本地网页与独立 Worker 已恢复；网页健康接口与账号会话接口均返回200，网页及 Worker 错误日志为空。
