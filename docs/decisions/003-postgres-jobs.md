# 003：PostgreSQL 队列与受执行权保护的任务

状态：当前采用。

## 背景

重复点击、回执丢失、Worker 中途退出可能导致重复任务、重复扣额或旧进程覆盖结果。

## 决策

pg-boss 与业务数据共用 PostgreSQL。业务意图、额度和队列入队在同一事务提交；owner + requestKey 定位原操作，请求内容变化拒绝重放。

执行者验证队列 claim、有效期、尝试次数和资源归属；进度及结果写入受同一执行权约束。最终业务结果与队列完成共同提交。外部 I/O 放在事务外，不能长时间持有资源锁等待供应商。

## 替代方案与代价

Redis/BullMQ 适合部分调度场景，但增加独立服务和跨库提交窗口。当前业务规模优先使用已有数据库，代价是队列与业务共用数据库容量，需关注连接、积压和维护。

执行权和幂等不等于外部 API exactly-once。调用已发生但响应丢失时，供应商可能已计费；保留尝试审计和明确重试语义，而不是承诺无法兑现的绝对去重。

## 实现与验证

[队列模块](../../server/queue)、[Worker](../../server/worker)、[失败恢复](../FAILURE_RECOVERY.md)。故障测试需要覆盖旧 claim、事务回滚、进程退出、同键重放和配额，而非只证明任务成功一次。
