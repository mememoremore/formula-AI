# 001：Nuxt 业务入口与独立执行进程

状态：当前采用。

## 背景

页面、认证、公式库和异步任务属于同一产品；Python 模型依赖及内存需求与 Node 不同。把推理塞入浏览器请求会扩大超时和部署耦合。

## 决策

Nuxt 提供页面与同源 API，服务端按认证、业务、数据库、资源、Worker 分层。Node Worker 执行长任务，Python 通过私有 HTTP 协议提供 CPU 推理。生产分别运行容器，权重只读挂载，不打入源码或应用镜像。

## 替代方案与代价

独立 NestJS 后端可以提供另一套模块体系，但当前会增加认证、部署与契约维护；Python 子进程直调减少 HTTP，却把依赖、取消和故障隔离绑在 Node 生命周期上。当前选择保留简单业务入口，同时承担进程间协议与健康检查成本。

不是微服务拆分越多越好。只有出现独立团队、扩容或权限边界需求，再评估更大拆分。模型来源与训练归属必须单独说明。
