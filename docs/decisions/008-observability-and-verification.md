# 008：可选观测与独立验证环境

状态：当前采用。

## 背景

异步任务跨浏览器、API、Worker 和 Python，仅凭一条 HTTP 日志无法定位完整问题。另一方面，收集原始用户数据或让监控成为业务依赖会引入额外风险。

## 决策

使用 OpenTelemetry 关联 trace/span，结构化日志写入 Loki，trace 写入 Tempo，指标由 Prometheus 采集，Grafana 统一查询；Alloy 负责采集转发。自动错误中心聚合受控前端异常、API 和任务/Python 故障。

只允许安全诊断字段，账号采用受控引用，不采集原始正文、密码、Cookie 或图片。观测可关闭，本机面板仅回环访问并要求登录。告警邮件显式启用，本地默认关闭，与注册邮件独立。

验证分为无真实依赖的单元/协议、清单绑定的隔离集成/浏览器，以及单独执行的真实模型/供应商联调。CI 不需要开发者私有 Key。

## 替代方案与代价

只看容器 stdout 成本低但跨服务检索困难；直接接第三方全量错误采集更省配置，却需要重新评估内容、成本与数据边界。当前自托管组件较多，资源占用和维护成本可观，小内存服务器不默认运行全套。

隔离环境增加启动时间，但可以检验真实事务、队列与存储行为，不把替身测试包装成真实模型效果。指标空样本不能解释成百分之百成功。
