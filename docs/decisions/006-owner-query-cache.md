# 006：账号范围的服务端状态缓存

状态：当前采用。

## 背景

公式库、详情、分类与统计相互依赖。各页面手写加载、刷新和写后同步会重复实现，且容易在账号切换或搜索乱序时显示旧数据。

## 决策

采用 TanStack Vue Query 管理服务端读取状态，每个 Nuxt 实例独立创建 QueryClient，SSR 通过 dehydration/hydration 衔接。query key 包含确认的 owner 和筛选参数，账号变化先阻断旧数据展示并取消/清理缓存。

mutation 复用统一失效逻辑。写入不自动重试，不实现离线意图队列；幂等回执由业务维护，响应不确定时重放原键和原请求。表单、裁剪等本地状态继续使用 Vue 状态。

## 替代方案与代价

Nuxt 读取能力可以继续用于合适场景，但不再让每页自己维护跨页面写后同步。Query 增加依赖、键设计与 SSR 生命周期约束；它不会自动理解账号边界、写幂等或 SSE 快照版本，需要明确接入。

不以“接入了缓存库”代替后端鉴权，也不把全部数据同时存入多份响应式副本。
