# 007：Zod 共享结构与专用规则

状态：当前采用。

## 背景

前端、服务端 parser、模型输出与恢复回执分别手写结构会漂移。一次“统一校验”也可能意外改变错误顺序、归一化和旧数据兼容。

## 决策

领域结构集中在 shared/schemas，类型尽量从 schema 推导，parser 保留可展示业务错误。维持原有 ID 形状、UTF-16 长度和 trim/NFC 顺序，不自动 coerce。新提交归一化与持久回执原样验证分离。

结构化解释严格校验 schemaVersion、字段、数量和长度，再执行数学语法检查。Python 响应关联 requestId 并校验内容边界。请求字节、认证、CSRF、图像、遥测脱敏、状态机和事务仍由专用实现负责。

## 替代方案与代价

全部手写校验依赖纪律维持一致；把所有事情塞进 Zod 则模糊职责并增加兼容风险。当前共享结构但保留专用规则，代价是需要说明哪些边界有意不统一。

渲染成功不是数学正确，schema 验证也不是权限校验。错误不能直接序列化原始输入或完整 issues。
