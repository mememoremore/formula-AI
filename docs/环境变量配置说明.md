# 环境变量配置说明

`.env`是本机运行配置，采用`变量名=值`的格式；`#`开头是注释，不参与运行。`.env.example`是供新环境参考的模板，不会替代当前`.env`。两份文件现已补上中文注释，说明中不包含实际密码或密钥。

变量名是程序读取配置时约定的标识，因此仍保留英文；改成中文名称，程序就不能按现有代码读取。`NUXT_`对应Nuxt的运行配置，例如`NUXT_AI_PROVIDER`对应`runtimeConfig.aiProvider`。它们不带`PUBLIC`，属于当前项目的服务端配置；Worker和脚本也会直接读取所需变量。

## 数据库：应用连接和Docker初始化

| 变量                | 含义                                               |
| ------------------- | -------------------------------------------------- |
| `NUXT_DATABASE_URL` | Nuxt、Prisma和Worker实际连接PostgreSQL的完整地址   |
| `POSTGRES_USER`     | Docker数据库首次初始化时创建的用户名               |
| `POSTGRES_PASSWORD` | 首次初始化使用的数据库密码，须与连接串中的密码一致 |
| `POSTGRES_DB`       | 初始化的数据库名，须与连接串末尾一致               |
| `POSTGRES_PORT`     | 数据库映射到Windows本机的端口，默认5432            |

连接串的结构是：

```text
postgresql://用户名:密码@主机:端口/数据库名
```

`127.0.0.1`表示当前电脑。当前Nuxt和Worker运行在Windows本机，通过映射端口连接Docker里的数据库。Docker容器内端口保持5432；如果把本机映射改成其他端口，也要对应更新应用连接地址。

这些`POSTGRES_*`变量主要用于初始化，不是每次启动都重建账号；已有数据卷时，仅改`.env`密码不会自动修改数据库里的真实密码。它们也不是用户登录本产品时使用的邮箱密码。操作细节见 [数据库操作手册](数据库操作手册.md)。

## Python图片识别

| 变量                           | 含义                                                                 |
| ------------------------------ | -------------------------------------------------------------------- |
| `NUXT_RECOGNITION_PROVIDER`    | `mock` 使用模拟识别，`python` 使用真实 Python 服务                   |
| `NUXT_RECOGNITION_SERVICE_URL` | Worker 调用的 Python 基础地址，本机默认 `http://127.0.0.1:8001`      |
| `NUXT_RECOGNITION_API_KEY`     | Worker 和 Python 共用的私有服务密钥，由初始化脚本生成                |
| `RECOGNITION_MODEL_PATH`       | Compose 挂载的模型目录，默认 `../model`，相对于项目中的 compose.yaml |
| `RECOGNITION_PORT`             | Python 容器映射到本机的端口，默认8001，容器内部为8000                |
| `RECOGNITION_CPU_THREADS`      | Python CPU推理线程数，默认4；服务内部仍只同时执行一路推理            |

Docker识别服务和Node适配器通过这些变量衔接。运行 `npm run recognition:env` 检查模型目录并补充缺少的识别配置，保留原有非空值；启用真实识别时应明确设置 `NUXT_RECOGNITION_PROVIDER=python`，启动识别容器后重启 Worker。Python 模式配置缺失会明确失败，不会退回模拟。

它们与DeepSeek配置相互独立：Python负责图片转LaTeX，DeepSeek负责解释和追问。若修改 `RECOGNITION_PORT`，也要更新服务地址中的端口；修改密钥后应重新创建识别容器并重启 Worker。Docker服务接收的内部变量名是 `RECOGNITION_API_KEY`，由 Compose 从 `NUXT_RECOGNITION_API_KEY` 映射，不必另填一套密钥。

## DeepSeek解释与追问

| 变量               | 含义                                                     |
| ------------------ | -------------------------------------------------------- |
| `NUXT_AI_PROVIDER` | 选择回答来源：`deepseek`调用真实服务，`mock`使用固定模拟 |
| `NUXT_AI_API_KEY`  | 本项目向DeepSeek发送请求时使用的API密钥                  |
| `NUXT_AI_MODEL`    | 模型名称，当前配置为`deepseek-flash`                     |
| `NUXT_AI_BASE_URL` | 模型API的基础地址，官方服务为`https://api.deepseek.com`  |

模型名称决定调用哪个模型；基础地址决定请求发往哪里；密钥证明你有调用权限。这与打开DeepSeek聊天网页的地址和登录密码不是同一回事。

当前已完成一次真实调用。密钥只由服务端读取，页面请求本项目的同源API。启用方法见 [DeepSeek配置与联调手册](DeepSeek配置与联调手册.md)，验证结果见 [真实联调记录](DeepSeek真实联调记录.md)。

## 用户登录与会话

| 变量                 | 含义                                                          |
| -------------------- | ------------------------------------------------------------- |
| `NUXT_AUTH_SECRET`   | Better Auth用于会话签名校验的随机密钥，不是某位用户的密码     |
| `NUXT_AUTH_BASE_URL` | 本产品账号服务所在的网站根地址，本机为`http://127.0.0.1:3000` |

会话密钥由服务端保管，当前代码要求至少32个字符。更改后会影响已有会话校验；`npm run auth:env`只补齐缺少的值，不会主动替换已有非空值。部署后网站根地址应对应实际的HTTPS访问地址。

## 私有图片与Word存储

| 变量                             | 含义                                                |
| -------------------------------- | --------------------------------------------------- |
| `NUXT_STORAGE_ENDPOINT`          | S3兼容存储的API入口；当前本机SeaweedFS使用8333端口  |
| `NUXT_STORAGE_REGION`            | 请求签名使用的区域标识；本机兼容服务采用`us-east-1` |
| `NUXT_STORAGE_BUCKET`            | 存储桶名称，可以理解为保存对象的逻辑容器            |
| `NUXT_STORAGE_ACCESS_KEY_ID`     | 存储访问凭据的标识，用于识别调用身份                |
| `NUXT_STORAGE_SECRET_ACCESS_KEY` | 对应的秘密密钥，用于生成请求签名                    |

这里保存的是图片和Word文件本体，数据库保存文件归属、状态、对象键等信息。当前连接本机SeaweedFS，并非必须使用AWS；`us-east-1`在此作为兼容请求的约定值，不表示文件被上传到美国。是否访问远程存储由实际Endpoint决定。

Access Key ID与Secret Access Key是同一组凭据，不能分别任意修改。应用和本机存储服务需要使用相匹配的配置。说明见 [私有对象存储操作手册](私有对象存储操作手册.md)。

## 每日额度和Word转换工具

以下变量在模板中提供，即使当前`.env`没有，也会使用代码默认值：

| 变量                           | 含义及默认行为                                                                |
| ------------------------------ | ----------------------------------------------------------------------------- |
| `NUXT_RECOGNITION_DAILY_LIMIT` | 每位用户每天接受的识别任务数，默认50                                          |
| `NUXT_CHAT_DAILY_LIMIT`        | 每位用户每天接受的对话轮数，默认30                                            |
| `NUXT_EXPORT_DAILY_LIMIT`      | 每位用户每天接受的Word导出任务数，默认20                                      |
| `PANDOC_PATH`                  | Pandoc可执行文件的完整路径；未配置时先寻找Windows项目便携版，否则使用系统PATH |

三项额度按UTC日期统计，即北京时间每天08:00重置，允许配置为1～10000的整数。自动重试不重复扣额度，接受后处理失败仍占用本次额度；这不是DeepSeek的Token或费用限额。

Pandoc是LaTeX转原生可编辑Word公式时使用的工具，不是模型服务。当前项目已有便携版，因此可以不填路径。任务和导出说明见 [后台任务与导出操作手册](后台任务与导出操作手册.md)。

## 英文注释原来在说什么

- “首日前端与模拟API可以不配置数据库或模型密钥”：描述最初演示阶段。当前账号、上传和队列功能已经依赖数据库，因此现已改成符合当前阶段的中文说明。
- “仅限本地开发，换环境前修改”：当前Docker连接信息面向本机，正式部署应配置实际环境的数据库、存储和访问地址。
- 模板中关于`db:env`、`auth:env`、`storage:env`的注释：说明这些命令如何创建或补齐配置，不会覆盖已有非空配置。

`.env`中的配置值已保留，本次只更新注释。今后修改实际配置值，建议同时重启Nuxt和Worker；Nuxt开发模式可能检测文件变化后自动重启，但独立Worker不会跟着自动重启。注释本身不改变运行逻辑。
