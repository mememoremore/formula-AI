# R5 公式库重构与验收说明

日期：2026-10-27。基线 R4 `3f79273`，分支 `refactor/r5-library`。本轮完成后停止，不进入 R6。

## 1. 现状盘点与范围

已阅读 R2/R3/R4 验收说明、《Formula重构.md》及当前公式库、账号/游客/历史、收藏、分类、分页、轮询和相关 API/测试。仓库没有独立 R0 报告文件，未声称读过不存在的文件。

保留：全部、收藏、最近识别、名称/LaTeX 搜索、分类筛选、账号分类管理/归类、游客新建分类、加载更多、详情入口、原图缩略图、游客本机持久化、错误重试、旧地址兼容。没有新增后端接口或 R18—R21 功能。

## 3. Mobile First 与桌面决策

先验收 320/390/430px，再验收 768/1024/1440px。标题与纸页插画使用正常网格，移除原负 right；没有全局 overflow hidden。R3 遗留的公式库装饰越界已在三种手机宽度验证修复。

| 视口        | 容器和卡片                                                   |
| ----------- | ------------------------------------------------------------ |
| 320/390/430 | 单列，宽度不超过视口；主要筛选、搜索、收藏至少 44px 触控高度 |
| 768         | 保持最大 480px、单列                                         |
| 1024        | 使用 R3 workspace，在视口内展开，双列                        |
| 1440        | 最大 1080px、双列                                            |

仅公式库设置 contentWidth=workspace，全站默认、首页及 R3 宽度规则未改。LibraryGrid 使用唯一的公共类按祖先布局选择列数；compact 下仍单列。没有填充空白卡片来凑列数。

卡片标题和分类完整换行。数学区域放在导航链接外，可聚焦和独立滚动，避免拖动或键盘阅读公式时误触详情。收藏保留透明背景的独立爱心，不增加外圈。分类选中、视图活动项和 URL 搜索框均可辨认；分类区自动换行。

## 4. 筛选、分页和收藏

- URL 保留 view、space、q、category 和其他查询。显式搜索/分类及视图切换产生可返回的历史项；游客实时本地搜索使用 replace，避免每个字符产生历史项。
- 切换到最近识别清除不被账号历史 API 支持的搜索/分类，保留原有行为。旧 /account/...、/favorites、/history 继续通过 R3 规则规范化。
- 账号列表按 ownerId + kind 分组缓存；响应附加本地 context 标记，不改变服务端 DTO。只有当前筛选结果可显示。
- 聚合结果直接保存在 NuxtData，不再维护另一份 items/cursor 副本。合并同时去除跨页与页内重复，采用最新字段值。
- 初始缓存读取当前 NuxtData，而非只存初始页的 payload，因此详情返回不丢掉已加载页。仅 initial 可以复用；手动刷新和筛选变化必须真正请求。
- 追加请求带 AbortSignal；改变筛选、重载、离页或提交收藏后使旧追加失效。旧 finally 不覆盖新请求的 loading 状态。
- 追加失败保留已有记录和 cursor，重试不会重复追加。手动刷新公式列表从当前筛选第一页重读；详情返回则保留匹配窗口。
- 浏览器硬刷新保留 URL 筛选，但从第一页重新取数；窗口只保存在当前 SPA 会话，不把私有账号列表写入 localStorage。历史按钮刷新/轮询保留窗口，不等同于硬刷新整个应用。
- 取消收藏后在收藏视图移除该项、更新当前窗口及原详情缓存，使其他库视图下次读新状态。移除当前窗口全部收藏但还有下一页时，不误报整个收藏为空。
- 分类更新后重读分类计数与公式。只有分类读取成功且确认被删除时才清除失效筛选，读失败不擅自重置 URL。

## 5. 识别历史与身份边界

旧 AccountHistory 只根据第一页决定轮询；后页 PROCESSING 可长期停留。现在用一个 useTaskPolling 实例读取到已加载尾项，刷新整个窗口。新任务插入时仍保留原尾项，截取到尾项而非每次额外扩大整页；活动判断涵盖全部已加载记录。

useTaskPolling 仅新增可选 read/getCachedData，其他调用保留默认读取方式；取消后不得提交快照。历史追加期间暂停轮询，刷新按钮受 pending/loading 限制。临时失败保留成功快照和明确重试，权限失败沿用清空规则；离页停止定时器。

历史缓存按账号分组，返回时保留窗口并重新校验。详情页只把原历史缓存精确失效扩展为前缀，不改详情编辑逻辑。上传和识别完成页仍保留旧精确失效键，库返回重新校验保证兼容；R7 可再统一这些失效入口。

只在 Session 成功确认发生身份变化时清除私有库/历史/分类缓存。Nuxt 离页释放会话不是退出登录，不因此误清分页窗口。组件按身份重建；收藏及分类晚到响应不写回已卸载页面。

**边界：**列表 GET 不负责后端 reconcile。Worker 崩溃后业务状态未收敛属于 R13，前端不能自行判定 FAILED。本轮没有改变队列、重试、额度或任务终态。前端取消 HTTP 也不等于回滚已到达服务端的收藏/分类写入；提交结果不确定时仍应刷新核实。

## 8. 未验证、风险和 R6 建议

账号状态、写入、分页、故障和任务变化均由**仅预览层内存替身**提供；真实浏览器交互已测，不代表 Better Auth、数据库持久化或真实 Worker 联调。真实 API 仍为公式每页 20、历史每页 25，替身用小页快速验证边界，没有改变后端分页契约。未运行数据库集成测试、迁移、真实 Python/付费模型。

未做真机 Safari、软键盘与完整可访问性认证。历史刷新成本随加载窗口增长，15 秒期限与取消生效；大量记录/后端崩溃收敛仍需 R13/R17 专项。没有引入状态框架或新依赖，快照是有目的的失败回退，不是第二套可编辑业务数据。

R6 建议先手机 320/390/430，统一原图/公式/版本/编辑的阅读层级，复用独立公式滚动，验证编辑冲突、收藏与分类回写、返回完整列表上下文。逐步统一历史失效前缀；不要为视觉调整改动版本事务。

本轮以独立本地 Commit 交付，最终 Hash 在会话列出。需要回滚时经确认执行 `git revert <R5提交>`，不 reset --hard、不清理数据或用户资源、不推送远程。R5 完成后停止等待评审。
