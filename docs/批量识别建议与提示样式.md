## 建议的批量处理流程（尚未实现）

在首页“输入 LaTeX”下面新增“批量识别”入口，副文案“一次上传多张图片，按图片整理结果”。建议第一版每批最多10张，沿用现有上传格式及单图限制。

1. 选择多张图片：展示缩略图、数量，可删除误选图片并调整顺序。
2. 选择模式：每张单公式，或每张多公式。多公式沿用现有检测与区域裁剪，可逐张预览、调整后确认。
3. 后台排队：上传和识别控制并发与速率，显示总进度及每张图片的待处理、处理中、成功、失败状态。当前识别服务使用独占锁，适合串行推理。
4. 结果按图片分组：对应原图、裁剪区域和公式结果，顺序稳定；支持勾选复制、Word导出及分类。识别结果默认未分类。
5. 独立失败恢复：仅重试失败项，成功项保留，不重复创建公式；离开、刷新后可从批次记录继续查看。
6. 确认前展示预计任务数和剩余额度。多公式一张图片可能产生多个识别任务，不能只按图片数量估算用量。

实现建议：

- 复用已有上传、识别任务、单/多公式裁剪及导出服务。
- 新增受账号隔离的批次记录和子项，保存图片与任务对应关系。现有多公式结果页通过地址携带有限任务编号，不能直接承担可恢复的大批次。
- 让待上传图片也进入前端队列，遵守当前单账号上传、识别并发和速率限制；不要仅把文件输入框改成 multiple 就同时发出所有请求。
- 自动重试只适用于可确认的临时失败，复用原请求编号；未知提交结果先核对任务，避免重复占用额度。
- 第一版保持图片级进度与失败重试；自动旋转、复杂混排阅读顺序、去重等能力可在验证后扩展。

本轮按用户“有什么好建议”的请求提供方案，没有创建批量入口、空壳页面或修改数据库。批次持久化与迁移的具体设计留待实施时评审；当前识别、数据与额度规则保持原状。
