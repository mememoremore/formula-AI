# R1 测试隔离与验收说明

日期：2026-10-26。范围仅为测试、配置、安全守卫与质量检查；不修改页面、生产 API、Schema、Worker 事务或模型适配器。

原始基线：`eeb2665109db37d70d95e0efe2e4a1a114f39c3c`；标签 `baseline/pre-r1-20261026`。工作分支 `refactor/r1-test-baseline`。

## 1. 隔离结构

| 资源       | 原开发环境             | R1 测试环境                                                                |
| ---------- | ---------------------- | -------------------------------------------------------------------------- |
| 配置       | 根目录 `.env`          | 显式 `FORMULA_TEST_MANIFEST`，位于 `tmp/r1-test/运行UUID/environment.json` |
| API        | 3000                   | 127.0.0.1:3100，测试层增加精确身份路由                                     |
| PostgreSQL | 5432 / formula_ai      | 15432 / formula_test_随机后缀，随机独立账号凭据                            |
| pg-boss    | 开发数据库             | 同一测试数据库；不需要替换队列技术或更改业务队列名                         |
| 对象存储   | 8333 / formula-private | 18333 / formula-test-随机后缀，独立实例与随机凭据                          |
| 数据持久化 | 原有数据卷             | 两个新容器仅使用 tmpfs；不挂载开发数据                                     |
| 模型       | 开发 Python / DeepSeek | API 与 Worker 固定 mock；协议测试只连本机替身                              |
| Worker     | 原启动命令             | 测试守卫后才允许启动；集成套件直接执行受控任务，不并行启动后台 Worker      |

运行 UUID、Compose 项目、容器 ID、容器标签、端口映射、挂载类型和凭据必须一致。容器标签包含资源配置指纹。只支持本机 Docker 管道，不接受远程 Docker 上下文。

## 2. Fail-Closed 顺序

1. 在创建客户端、before/after、领取队列或清理前，拒绝缺失、格式错误、路径错误、环境变量冲突和非测试目标。
2. 只读 Docker inspect，核对两个容器的真实 ID、运行状态、标签、端口、环境及 tmpfs。任何已有磁盘数据挂载均拒绝。
3. 使用本次令牌读取测试 API 身份。服务端比较实际 runtimeConfig 的所有测试资源字段后才返回运行编号和配置指纹；不返回连接串或凭据。
4. 身份握手匹配后才进入集成测试。S3、DB、API 与 Worker 的变量来自同一清单，不读取开发 `.env`。
5. Node 网络守卫拒绝公网、开发默认端口；集成进程只开放 3100、15432、18333。Nuxt API 允许框架自身严格命名的本机 Nitro/Vite IPC。

Nuxt 内部 Worker 会添加框架变量：启动器仍检查完整调用环境；Worker 预加载器精确检查资源变量；身份路由再检查实际 runtimeConfig。不能用自报“test”字段代替核对。

`verifyTestTargets` 同时用于实际集成入口和注入式拒绝测试。拒绝测试不连接开发资源。所有测试均不包含真实付费模型密钥；缺密钥分类测试也被网络守卫保护。

## 3. 使用方法

从项目根目录执行，使用 package.json 要求的 Node 版本。原 `dev`、`worker`、数据库配置命令仍是开发命令，不能拿来启动测试资源。

```powershell
npm run test:env:create
# 将上一条最后输出的 environment.json 绝对路径粘贴到下面的输入中。
$env:FORMULA_TEST_MANIFEST = Read-Host '测试清单绝对路径'
npm run test:server
```

另开终端，设置同一个 `FORMULA_TEST_MANIFEST`：

```powershell
$env:FORMULA_TEST_MANIFEST = Read-Host '同一测试清单绝对路径'
npm run test:env:check
npm run test:integration
```

不要同时运行 `test:worker` 与任务测试：套件需要明确观察未消费、崩溃和重试状态。只有独立调试时才运行 `npm run test:worker`，该命令也必须先通过相同身份校验。

结束后先停止本次测试 API，再执行 `npm run test:env:stop`。停止只按已核对的两个容器 ID 执行，不运行 `down -v`，不清理原数据库或存储。tmpfs 在停止后丢失，下一次应创建全新运行；不能将旧清单自动复用为新环境。

若创建过程中失败，不执行后续迁移或测试。已经创建的本次测试容器可能保留，需根据本次 Compose 项目与标签检查后处理，不能执行全局 Docker 清理。

## 5. 契约修正

- workspace 的 HTTP helper 不再把 202 包装成伪造的 200。
- 验证真实 202、QUEUED、空 formulaId，测试 Worker 校验 taskId/ownerId 后执行，再通过 API 查询 COMPLETED 和公式。
- 并发重放保留同任务、同请求键、唯一公式、模式冲突与用户归属断言。
- 列表 DTO 精确字段列表补入当前公开的 imageId，并验证无原图时为 null；不放宽存储/认证字段检查。
- 旧 `/account/formulas/:id` 验证 302 及规范目标，再验证规范地址 200；继续核对原图和越权访问。
- fixture 和集成测试不再加载 dotenv；崩溃子进程同样先过守卫。旧验收产物不覆盖，新产物写入 tmp。

## 6. 构建、素材与剩余边界

准确缺失：`public/images/home-paper.webp`、`public/images/library-paper.webp`、`public/images/default-avatar.webp`。未创造占位图、未更改 Vue 引用、未降低检查。

隔离构建写入 `tmp/r1-test/build`，不使用旧 `.output`。凭据扫描要求本次构建 completed、源码及 public 指纹一致、全部客户端文件 SHA-256 一致。新构建开始即作废旧凭据；失败记录不能得到通过，也不再自动 skip。

本轮无测试跳过；生产构建成功路径及随后客户端扫描因原素材缺失尚未验证。浏览器视觉、真实 Python 权重推理、真实模型调用、生产部署、Linux 实机尚未验收。Linux IPC 名称通过纯函数测试，但不等于 Linux 部署已验证。

R1 已建立可安全运行的回归入口，是否进入 R2 由评审决定；不能把当前仓库描述为全量质量门禁已通过。

已实际验证两条拒绝命令：未设置清单时 `test:integration` 在测试注册前以非零退出；构建失败凭据的客户端扫描在 completed 校验处拒绝，未扫描旧产物。二者是安全拒绝证据，不计入通过的业务测试数量。

首轮集成测试为 88/90，修正公开 imageId 与规范地址两个旧契约后复验为 93/93（新增三项隔离测试）。不删除失败项或降低安全校验。另有 28 单元、20 协议、7 DOCX、7 Python 测试，共 155 个最终通过项。
