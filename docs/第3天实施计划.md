# Day 3 实施计划

用户已授权按已确认的 15 天计划完成第三天，并要求交付数据库与架构决策说明。使用 writing-plans 技能梳理任务，在当前工程顺序执行。

## 范围与设计

保留 Nuxt 与现有前端演示流程；新增 PostgreSQL 17、Prisma 7.10.1、真实迁移、服务端连接入口、数据操作函数、种子数据和数据库集成检查。真实登录、前端数据切换、上传、Worker 和大模型仍按各自排期实施，不新增可绕过鉴权的公开数据库接口。

九张业务表：User、StoredFile、RecognitionTask、Formula、FormulaVersion、Category、Favorite、Conversation、ChatMessage。

- 私有资源显式存 ownerId，用组合外键约束跨表关联的用户一致性；数据库约束不等于读取权限，正式鉴权在第四天接入。
- 原始识别写入第一条公式版本，修改只新增版本。最新版本按递增编号读取，不维护重复的当前 LaTeX。
- 对话绑定具体版本；收藏采用独立关系表；分类为单层，一条公式至多一个分类。
- 文件只保存私有存储定位及元数据，不将图片二进制或临时签名 URL 存入业务表。
- 识别任务保留状态、有限尝试计数和每用户幂等键；队列执行、恢复及额度逻辑不在本次实现。
- Prisma schema 表达关系和普通约束；SQL 迁移补充检查约束与禁止覆盖公式版本的触发器，明确记录 ORM 表达能力的边界。

## 验收命令

`npm run db:env` → `npm run db:up` → `npm run db:generate` → `npm run db:migrate`（执行两次）→ `npm run db:seed`（执行两次）→ `npm run test:db` → `npm run typecheck` → `npm run build`。

数据库测试使用临时测试用户，并只清理本次生成的用户数据。不得执行清空现有数据库的 reset，不删除 Docker 数据卷，不输出连接密码。
