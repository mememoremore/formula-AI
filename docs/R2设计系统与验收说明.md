已有本地素材均为完整 PNG 设计板，没有可直接使用的透明独立源图。未下载外部图片、未裁切设计板冒充资源。三张 SVG 在仓库内原创绘制，沿用 PaperArtwork 的暖纸、点阵、紫色胶带和细线几何语言；头像为浅紫人物插画。三处只更换静态引用，未删除视觉内容或修改数据逻辑。SVG 中公式仅为装饰，真实数学内容继续由 KaTeX 渲染。

## 2. Token 来源与兼容策略

`app/assets/css/tokens.css` 是唯一全局 Token 定义来源，由 main.css 导入。没有引入 UI 框架或新依赖。

| 类别 | 规范                                                                                                |
| ---- | --------------------------------------------------------------------------------------------------- |
| 品牌 | 主色 #683fff，柔紫背景；原有主按钮渐变在生产保持兼容                                                |
| 文本 | 主文字 #151631；推荐辅助文字 #62657d；原 muted #8588a6 暂保留给旧使用点，不声称旧页面全部满足对比度 |
| 状态 | 成功 #25674e / #edf7f1；警告 #8a5816 / #fff6e8；错误 #b83d52 / #fff1f3；信息 #3a5c98 / #eef3fc      |
| 字体 | 系统中文无衬线；12/14/16/20/28/36 字号尺度；正文行高 1.75，标题 1.35                                |
| 数学 | 保留 MathFormula + KaTeX 与 MathML，独立横向滚动，不压缩整页；长公式区域可聚焦以便键盘操作          |
| 间距 | 4/8/12/16/20/24/32/40/48；旧布局关键有效值保留                                                      |
| 圆角 | 小元素 8；控件 15；卡片 22；弹窗 24；胶囊 999                                                       |
| 阴影 | 内容卡片轻阴影；弹窗单独遮罩和层级，不在每个元素叠加强阴影                                          |
| 动作 | 44px 触控目标；160ms 轻量过渡；reduced-motion 时停用动画                                            |
| 焦点 | 键盘 focus-visible 使用 3px #7450cf；输入普通鼠标聚焦保留轻边框，不强加整圈键盘轮廓                 |

样板显式覆写同一套变量中的主按钮渐变和 muted，验证更深、可读的候选值。没有把样板的字体、布局和全部颜色直接应用到所有业务页。按钮渐变端点、样板正文及四种状态文字的最低实测对比度为 **4.998:1**；这不是对全站、全部背景或全部交互状态的无障碍认证。

## 4. 公共组件与使用规范

| 现有实现                                        | 规范与本轮范围                                                                                                     |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| .button / primary / white / secondary / outline | 保留 class API；主次操作清楚；disabled 不可点击；aria-busy 配合不可重复提交与文字状态，不只显示转圈                |
| .input、textarea.input、field-label             | 始终可见标签；错误用 aria-invalid + aria-describedby + 文字；disabled 与 readonly 含义分开；不改 ChatComposer 行为 |
| .card                                           | 白色内容容器，22px 圆角，轻阴影；不用装饰空卡占据 AI 正文                                                          |
| AppModal                                        | 保留原生 dialog、名称、关闭与 Esc；只将圆角、阴影、遮罩引用 Token；焦点返回已实测                                  |
| AppToast                                        | 复用原组件；不内置请求；本轮未改其定时器或定位；无导航页的最终定位由 R3 处理                                       |
| EmptyState                                      | 复用书本图标与标题说明；区分真空态和失败，不为名单重复创建另一套组件                                               |
| 加载                                            | 保留 NuxtLoadingIndicator；新增轻量 skeleton/busy-indicator class 作为可复用样式，不引入加载框架                   |
| 错误                                            | 复用 status-panel / error-text 及语义容器；错误需要恢复动作，不建立重复 ErrorState 抽象                            |
| .badge                                          | 新增 success/warning/danger/info 语义变体，状态必须有文字，不仅靠颜色                                              |
| PageHeader / PageIntro                          | 保留原组件和路由职责；样板复用 PageIntro 验证层级；不把返回导航改成展示组件内部的新业务                            |
| UserAvatar / FavoriteButton / MathFormula       | 样板使用真实组件；只改头像缺失资源，不修改收藏请求或公式安全渲染                                                   |

AppBrand 当前内部有会话请求，因此样板不用它伪装成纯展示组件，也不在 R2 顺便重构身份逻辑。样板品牌直接使用已有 favicon 和文字。后续 R3/R9 再处理品牌与身份装配边界。

尺寸基准：普通按钮最小高 50px、padding 12/18、gap 8；图标按钮 44px；输入 padding 13/15、正文 14px、约 50px 高；卡片不全局强加 padding，样板桌面 24、移动 20。AppModal 宽度不超过 456px、padding 24/24/30、最大高 88dvh；AppToast 最大宽 400px、padding 13/18、13px 字、3.5 秒现有持续时间。EmptyState 继续使用现有 64px 图标；样板局部调整留白。PageIntro 28px 标题，PageHeader 保留原尺寸；后续页面确认后再迁移，避免为统一字号强改全站。

## 5. 响应式与预览方式

```powershell
npm run preview:design
```

打开 `http://127.0.0.1:3200/__preview`。仅显式加载 `tests/design-preview` Nuxt 层才有该页面，不新增 app/pages 正式路由。启动器复用 R1 的干净环境：空数据库/认证/存储凭据、mock 模型、空 dotenv，不创建 Docker 资源，不执行迁移。

- 默认：480px 主体居中，移动端单列；生产宽度保持 480px。
- 对比：`/__preview?layout=wide`，桌面预览最大 1080px、双列，窄屏仍单列。该策略尚未进入正式页面。
- 内容区域留出底部安全区；本轮不改变 AppBottomNav，也不宣称 iOS 刘海或软键盘已真机验收。
- 长公式仅内部滚动；没有通过缩小公式或隐藏溢出来掩盖问题。

执行命令：`check:assets`、`typecheck`、`typecheck:design`、`test:unit`、本轮文件 Prettier、`git diff --check`、`check:build` 及构建后的客户端产物扫描。详细最终结果与提交信息见本次会话交付报告。

最终结果：资源缺失 0；生产构建成功；149 个客户端文件清单对应的私有配置检查 1/1；类型检查与样板类型检查通过；单元 28/28；浏览器 30/30；本轮修改文件格式与 Diff 检查通过。另在 1440px 视口验证 200% CSS 放大，页面 scrollWidth 与 clientWidth 均为 1440；这不等于所有真机缩放行为已验收。构建有两条插件耗时提示，无构建失败，本轮不扩大到打包性能优化。

生产产物静态审查确认没有 `/__preview` 路由。后端、Schema、迁移、Worker、权限、额度、接口契约、依赖及锁文件未改变；开发 `.env` 与原始备份哈希一致。

R1 的历史格式清单不作为 R2 批量整理任务。首页、公式库因资源引用属于本轮必要修改，按要求只格式化本轮触及的文件，没有为了全仓变绿处理其他旧文件。

全仓格式检查仍有 12 个原有文件不合规；R1 的 15 项中，本轮必要触及的 CSS 与两个页面格式随修改收敛，其余保持原样。

未运行数据库/队列集成测试：本轮禁止迁移且未改后端业务，不另建测试数据库。未调用 DeepSeek、未加载 Python 权重、未执行真实浏览器登录或数据提交。浏览器移动视口不等于实体手机验收。

## 9. 后续轮次建议及回滚

R3 先确认桌面策略，再处理布局、安全区、导航返回和 Toast 定位。R4/R5 采用已落地插画与卡片规范，分别处理首页、公式库状态。R6 保持长公式、原图、编辑与版本的阅读层级。R7 统一上传及任务反馈。R8 以连续正文和 SSE 内容为中心，减少大块空卡；不照搬图稿中的装饰步骤。R9 处理身份、头像及资料，R10 覆盖辅助页和错误页。

本轮没有将新的辅助文字、渐变与桌面宽布局批量应用到全站；需要用户确认样板后再按轮次推进。Git 原始基线及 R1 提交保留，回滚采用本轮提交的可审查反向提交或从 R1 恢复到新目录，不使用 reset --hard 或清理业务数据。

交付拆为两个提交：R2-A 只包含三张原创资源与三处引用/必要格式；R2-B 包含 Token、样板及文档。若只否决视觉方案，可仅反向 R2-B，保留资源与构建修复。回退 R2-A 会恢复原来的三项资源缺失，因此不建议为调整样板而整体回到 R1。
