# 数据库操作手册

## 启动与迁移

数据库使用 PostgreSQL，Prisma schema 和迁移是结构来源。账号、私有文件元数据、公式、会话、任务与额度都依赖数据库，不能用旧访客演示来验证这些能力。

首次本地启动：

    npm run db:env
    npm run db:up
    npm run db:migrate
    npm run db:check
    npm run worker:setup

db:env 生成或补齐本机配置，db:up 等待 Compose 数据库健康；db:migrate 执行已有迁移，不创建任意新结构。worker:setup 初始化 pg-boss 结构与业务队列。具体服务配置见[环境变量](环境变量配置说明.md)。

    npm run db:status
    npm run db:validate
    npm run db:generate

开发确实需要修改模型时，先评估兼容性、编辑 prisma/schema.prisma，再在个人开发库运行 db:dev 生成新迁移，审查 SQL 并在隔离库验证。不要修改已被其他环境应用的迁移，不要用 reset 解决共享或生产库的问题。

## 数据关系

主要模型与归属关系见[架构说明](ARCHITECTURE.md)。业务表与 pgboss 队列表共用 PostgreSQL，因此提交任务、项目额度和入队可在同一事务中提交。不要手动删除队列记录后宣称业务任务已完成。

查询与变更必须限定当前会话账号。复合外键、唯一键和触发器提供额外保护，不能代替 API 鉴权。编辑的预期状态、幂等冲突和 Worker 执行权是业务协议的一部分。

db:studio 可以人工查看开发数据，但具有修改能力；不要把 Studio 暴露到公网或把生产数据库连接交给同事。db:seed 是显式演示数据入口，不应对正式用户库随意运行。

## 备份与恢复

数据库备份只覆盖数据库，不覆盖对象存储、模型、.env 或 TLS 私钥。生产备份应包含数据库逻辑备份、对象存储数据及独立保存的必要配置，并记录版本和时间。[部署手册](../deploy/README.md)提供单机操作与回退流程。

恢复应先放入独立数据库和独立存储，核对账号、公式、文件引用、队列与下载；验证成功后再计划切换。不能把本机开发库直接覆盖到已有生产库。备份包含个人数据，禁止进入 Git 或公开测试附件。

## 停止与故障检查

    docker compose ps postgres
    docker compose logs --tail 80 postgres
    npm run db:down

db:down 只停止服务，数据卷保留。不要使用删除卷或全局 Docker 清理作为日常停机命令。

| 现象               | 检查                                                           |
| ------------------ | -------------------------------------------------------------- |
| 无法连接           | 数据库健康、实际地址/端口、当前终端配置                        |
| 密码不一致         | 初始化环境变量只在新卷生效；修改 .env 不等于修改已有数据库密码 |
| API 正常但任务不动 | Worker、pg-boss 队列和任务执行状态                             |
| 迁移失败           | 先记录当前 migration 状态并阅读 SQL，不直接删表重来            |
| 测试拒绝运行       | 使用专用环境清单，不能把开发库伪装成测试库                     |

数据库测试使用 [test:isolated](TESTING.md)，不使用日常账号数据做回归。日志与调用链见[观测指南](OBSERVABILITY.md)。
