## 首次配置

本次使用 Docker 只运行 PostgreSQL，Nuxt 仍在本机运行。先启动 Docker Desktop，然后在项目根目录执行：

```powershell
npm install
npm run db:env
npm run auth:env
npm run db:up
npm run db:migrate
npm run db:seed
npm run db:check
```

`db:env` 生成随机本机密码并同步填入连接串，已有 `.env` 不会被覆盖。密码不会打印到终端，`.env` 已被 Git 忽略。

默认数据库名为 `formula_ai`，用户为 `formula`，端口为 `127.0.0.1:5432`。实际密码保存在本机 `.env`，不是 `.env.example` 中的示例密码。

本次创建的容器是 `formula-ai-postgres-1`，数据卷是 `formula-ai_postgres_data`。端口只绑定本机。前端仍通过 `npm run dev` 启动，当前演示页面不依赖数据库在线。

## 日常命令

| 命令                                       | 用途                                                          |
| ------------------------------------------ | ------------------------------------------------------------- |
| `npm run db:up`                            | 启动 PostgreSQL，并等待健康检查                               |
| `npm run db:down`                          | 停止 PostgreSQL，不删除数据卷                                 |
| `npm run db:generate`                      | 根据 schema 生成 Prisma Client                                |
| `npm run db:validate`                      | 检查 Prisma schema                                            |
| `npm run db:migrate`                       | 应用仓库中已有迁移，可重复执行                                |
| `npm run db:dev -- --name describe_change` | 修改 schema 后创建开发迁移，需要开发库及 shadow database 权限 |
| `npm run db:status`                        | 查看迁移状态                                                  |
| `npm run db:seed`                          | 写入固定开发样例，不覆盖已有行                                |
| `npm run db:check`                         | 检查连接、数据库版本和表计数，不打印密码                      |
| `npm run db:studio`                        | 通过 Prisma Studio 查看数据                                   |
| `npm run test:db`                          | 执行真实 PostgreSQL 集成检查                                  |
| `npm run test:private-config`              | 构建后检查客户端产物是否包含数据库地址或密码                  |

生成的客户端位于 `server/generated/prisma/`，不要手工修改；生产构建也会自动 generate。

## 查看数据库

```powershell
docker compose ps
docker compose exec postgres pg_isready -U formula -d formula_ai
docker compose exec postgres psql -U formula -d formula_ai
```

进入 psql 后可执行：

```sql
\dt
SELECT id, title FROM formulas;
SELECT "formulaId", number, latex, origin FROM formula_versions ORDER BY "formulaId", number;
\q
```

桌面数据库客户端的主机填 `127.0.0.1`，其他参数与 `.env` 一致，密码从本机文件查看，不将带密码的连接串写入项目文档。

## 后续改表与迁移规则

目前有六份迁移：初始结构、CHECK/触发器、Day 4 认证表、Day 5～6 上传与历史、Day8～9 队列/轮次/导出/额度，以及第13天流式片段和回答来源。应用仍为16张表。已经应用的迁移不要回头修改，使用新迁移表达变化。

1. 修改 `prisma/schema.prisma`。
2. 执行 `npm run db:dev -- --name describe_change` 并审阅生成的 SQL。
3. 自定义规则不能完整写进 schema 时，在应用迁移前补充 SQL，或另建迁移。
4. 执行 generate、类型检查及数据库测试。
5. 部署时执行 `npm run db:migrate`，应用已经审阅过的迁移。

`db:migrate` 不会重复建表或清空数据。不要将 `prisma migrate reset`、`docker compose down -v` 当作启动命令；本次没有执行它们。`db:dev` 若检测到不一致并建议 reset，应先检查数据和迁移，不直接确认重置。

## 使用已有本地 PostgreSQL

可以不使用 Docker：创建数据库和用户，将连接串填入 `.env` 的 `NUXT_DATABASE_URL`，再运行迁移。应用只依赖 PostgreSQL 连接，不依赖 Docker API。

如果 5432 已被其他数据库占用，同时修改 `POSTGRES_PORT` 和连接串端口，再重新启动容器。已有数据卷初始化后，修改 `.env` 的密码不会自动改变数据库用户密码。

## 开发与部署边界

- CLI、种子、测试通过 dotenv 读取本机 `.env`；Nuxt 服务端通过私有 runtimeConfig 获取连接。
- 生产 Node 服务需要注入 `NUXT_DATABASE_URL`，不会自动读取工程目录的 `.env`。
- 修改连接或 schema 后重启 Nuxt/Worker，避免热更新复用旧客户端。
- 当前开发用户有初始化和迁移权限；正式部署应区分迁移用户和受限运行用户。
- 命名数据卷不是备份，本次尚未做 Day 14 的备份恢复验收。
- 种子用户没有密码；文件是 PENDING 元数据；识别和消息为固定模拟样例。
- 登录后的上传、结果编辑、历史、分类和收藏已保存到账号；访客演示仍使用本机记录，不会自动导入。Day7 复用原表，没有增加迁移；设计理由见 [第7天开发说明](第7天开发说明.md)。图片内容存储配置见 [私有对象存储操作手册](私有对象存储操作手册.md)。
