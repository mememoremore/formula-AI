# 公式收藏位置与复制格式修复

日期：2026-11-08

## 结果与原因

爱心现在紧跟公式名称右边，“命名”保留在右侧。普通多公式和批量处理共用的区域选择中删除了“重新检测”。

旧“复制源公式”调用文本转换接口，将分式转为斜杠与括号，将部分上下标转为 Unicode 或括号写法，因此没有携带二维数学结构。现在按接收软件的能力提供四种表示：

| 入口         | 内容与用途                                                                                                                               |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 复制源公式   | 标准 Presentation MathML 文本；Word 等支持 MathML 的公式编辑器可以导入成可编辑公式。多条公式使用一个根节点与多行表格，避免只导入第一条。 |
| 复制网页公式 | HTML 中的 MathML，同时携带原始 LaTeX 文本表示；支持数学排版的网页编辑器可保留公式结构。                                                  |
| 复制公式图片 | 当前公式排版生成的 PNG；支持图片的聊天或文档可粘贴，图片不可直接编辑。                                                                   |
| 复制 LaTeX   | 保留完整源码，适合公式源码编辑器或普通文本输入；复制受限时仍显示手动复制文本。                                                           |

没有一种剪贴板格式能强制所有接收软件同时支持二维排版和公式编辑。“复制源公式”粘贴到不支持 MathML 的纯文本框会显示 MathML 源码，普通文本场景应使用 LaTeX；这不是原始图片的像素副本，也不会自动纠正识别错误。需要先核对识别结果，再用编辑公式或重新生成修正错误字符。

## 兼容性与未验证项

网页富格式在本机 Edge 验证，原生可编辑对象在本机 Word16.0 验证；未验证所有 WPS、其他 Office 版本、手机浏览器及第三方聊天工具。图片方式是否可粘贴、网页是否保留 MathML，最终由接收软件决定。现有可编辑 Word 导出作为另一条已提供的文档路径。

Word 的 HTML MathML 导入与裸 MathML 文本导入在不同版本上存在差异，因此本次通过实际粘贴选择了独立的 Word 源公式表示，没有把单一格式宣称为全平台通用。多条源公式组成一个多行公式对象，如需分别独立的公式对象，可逐条复制或使用可编辑 Word 导出。

没有引入新的技术债务；沿用既有 KaTeX、MathJax/Sharp、认证与文档渲染模块。

参考：[Microsoft MathML 支持](https://learn.microsoft.com/en-us/office/math/mathml)、[ClipboardItem 多种表示](https://developer.mozilla.org/en-US/docs/Web/API/ClipboardItem/ClipboardItem)。
