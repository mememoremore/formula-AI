# 第4天实施计划：登录、会话与私有资源

用户已授权开始 Day 4；沿用已确认的登录、会话和资源隔离设计。使用 brainstorming、writing-plans 梳理，并在当前会话顺序实现。现有目录不是 Git 仓库，不创建无关仓库或提交。

## 目标与选择

采用 Better Auth 的邮箱密码认证和 Prisma 适配器。相比自行组合密码哈希和 Cookie，认证协议、密码处理及会话交给成熟库；相比托管认证，不需要用户先注册外部服务。代价是本项目维护认证表、密钥与部署配置。

现有 User.id 与私有资源 ownerId 保持不变，认证名称映射到 displayName。新增账号、会话、验证表和持久化限流表，通过新迁移追加，不修改 Day 3 的迁移。会话保存在数据库，HttpOnly Cookie 携带签名令牌，不将令牌存入 localStorage。

演示首页、识别与 AI 仍可体验；新增 /account 作为正式账号空间，登录后查看真实数据库资源概况。现有浏览器演示记录不自动导入账号，不把演示记录算作云端数据。正式上传、公式编辑和分类操作仍按后续排期接入。

## 关键约定

- 密码最少 10、最多 128 个字符；注册昵称 1～100 字。邮箱去首尾空白并转小写。
- 会话最长 7 天、每日可续期，禁用客户端会话 Cookie 缓存，撤销后下一次受保护请求立即检查数据库。
- 身份与业务数据由同一个 User.id 关联；资源接口不接收可信用户身份参数。
- 认证请求限流写入 PostgreSQL，不引入 Redis。部署需正确设置站点 URL、HTTPS 和可信代理。
- 邮件验证、找回密码和社交登录未接入，本次界面不显示不可用按钮；未验证邮箱不能用于后续敏感邮箱所有权证明。
- 迁移与测试不清空数据库，测试仅清理临时创建的用户与限流键，不输出密码、Cookie 或真实配置。
