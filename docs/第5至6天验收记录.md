## 16 项新增检查

1. PNG 真实写入 S3；元数据属于当前用户，成功后才标记 READY，存储内容能解码。
2. JPEG 带 EXIF orientation=6，保存后宽高正确互换，EXIF/方向元数据移除。
3. 伪装格式、损坏 PNG、空内容及超过 10MB 字节的文件被服务器拒绝。
4. 没有 Content-Length 的分块上传同样返回 413，不依赖声明长度。
5. 压缩后很小、解码后 20004000 像素的 PNG 返回 413。
6. 上传请求重放返回同一文件；相同请求键更换内容返回 409，不重复建行。
7. 本人能读取原图；其他用户为 404，未登录为 401，S3 匿名读取真实对象为 403；不能识别他人的文件。
8. 模拟识别原子保存完成任务、公式及 v1，明确 isMock=true，忽略伪造 ownerId。
9. 两个并发相同识别请求返回同一公式；不同模式不能复用同一键。
10. 外部用户不能读取公式和追加版本，未登录不能上传或保存。
11. 修改后的 v2 可重新读取，原始 v1 和图片引用不变。
12. 两份旧版本并发修改只成功一份，另一份返回 409，版本号不重复。
13. 相同内容或仅改名称不产生额外版本，名称确实更新。
14. 账号历史每页 20 条，不重复、不混入另一个用户，外部游标为 404。
15. 注入 S3 写失败，文件不变为 READY；补偿后可用同一请求重试并复用文件 ID。
16. 跨站写入为 403，不完整的编辑参数为 400，不修改已有内容。

短暂的客户端连接复用竞争曾导致大尺寸样例测试连接重置；已将大图生成放到 HTTP 检查之前，并在超限响应关闭本次连接。最终开发与生产两轮 16 项均通过，没有跳过失败用例。

## 浏览器实际流程

独立 Playwright 会话依次完成：

```text
注册 → 上传真实 PNG → 自动保存固定模拟结果 → 详情显示原图
→ 刷新仍显示原图 → 编辑名称和 LaTeX → 保存 v2
→ 再次刷新读到 v2 → 展开 v1 确认原始内容保留
→ 打开账号历史 → 刷新仍有记录 → 退出 → 原详情要求重新登录
```

## 仍需明确的边界

- 当前识别是固定模拟结果；图片上传成功不等于实际识别成功率或真实模型已接入。
- 手机布局及图片选择经浏览器自动化验证；真实手机相机权限、相册及方向行为仍需真机体验，不宣称已完成所有机型测试。
- Clipboard API 受浏览器权限和安全上下文限制；页面有失败提示并保留可手动选择的 LaTeX，本次未把操作系统剪贴板兼容性当作全面验收结果。
- 文件上传两阶段提交有补偿，但未实现崩溃后自动恢复 PENDING；不是完整后台任务系统。
- 同一个浏览器页面内保留重试键；关闭页面不自动恢复未完成上传。Worker、可靠恢复、调用额度在后续阶段。
- 云端 HTTPS、存储账号最小权限、数据加密、高可用和备份恢复没有在本机单节点验收中完成。
- 账号分类收藏、真实 AI 对话、Word、邮箱验证和找回密码仍按后续范围处理。
