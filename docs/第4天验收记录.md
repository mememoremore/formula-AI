## 12 项认证检查具体覆盖什么

1. 注册复用 User.id、邮箱归一化、昵称映射、真实密码哈希可验证；请求不能指定 id 或伪造 emailVerified。
2. 未登录返回空会话；私有 API 为 401，账号页面跳转登录。
3. 短密码、空昵称、重复邮箱被拒绝；失败不产生半成品用户。
4. 登录签发 HttpOnly / SameSite=Lax Cookie；刷新保持身份；精简会话不返回令牌。连续渲染 A、B 与匿名页面不混用用户结果。
5. 账号概况只统计本人记录，伪造 ownerId 查询参数无效。
6. 两个真实账号可以读取自己的公式、版本、文件、任务、分类和对话；双向读取对方资源均为 404。文件响应不含存储定位。
7. 无效与不存在资源 ID 返回 404；数据函数缺失身份时不放宽查询。
8. 错误密码、篡改 Cookie 无法访问私有接口。
9. 不可信来源的登录和退出请求为 403，原会话不受影响。
10. 数据库中已过期的会话立即不能访问；其他用户会话保持可用。
11. 退出删除当前数据库会话；重放旧 Cookie 返回 401。
12. 两个独立认证实例共享数据库限流；12 个并发登录请求只放行 8 个，另外 4 个返回 429。

这些结果验证本次已开放的接口，不等于未来所有写接口已完成鉴权。新增上传、编辑、收藏和对话接口都必须复用会话守卫，并新增对应业务验收。

## 数据与进程处理

HTTP 集成测试仅删除本次随机邮箱对应的临时用户；并发限流测试只清理专用测试地址对应的限流键。浏览器测试只删除明确记录的两个验收邮箱，没有清空用户表、覆盖种子、重置数据库或删除数据卷。

验收后种子仍为 2 用户、2 文件、2 任务、2 公式、3 版本、2 分类、2 收藏、2 对话和 3 消息。认证表中的短期限流记录可以继续存在，不是新用户业务数据。

生产验收进程结束后恢复 `npm run dev`，数据库容器保留运行。用户仍使用原来的启动命令；本次没有改变全局 Node 安装。

## 已知边界与依赖扫描

- 尚未配置邮件发送，没有邮箱验证和找回密码；不宣称邮箱所有权已经确认。
- 本次验证本机 HTTP Cookie。部署 HTTPS、Secure Cookie、真实反向代理 IP 与线上备份仍需在部署阶段验收。
- 当前 HTTP 入口忽略客户端伪造的转发地址。经过反向代理时暂按代理连接地址计数，部署时需按真实拓扑配置可信代理。
- 演示识别和 AI 仍为模拟，演示修改没有自动存入账号；本次没有调用收费模型或发送邮件。
- 依赖扫描报告 **11 个 high 级依赖节点**，来源是上游 `braces <=3.0.3` 与 `node-forge <=1.4.0` 两类公告及它们的依赖链；当前注册表这两个包的 latest 仍分别为 3.0.3、1.4.0。没有用未发布版本覆盖，也没有强制降级 Nuxt。已更新 Nuxt 和 KaTeX，并记录扫描文件 `artifacts/dependency-audit-day4.json`。不能把此次业务验收理解为全依赖树安全审计通过，部署前需继续跟进上游修复。
