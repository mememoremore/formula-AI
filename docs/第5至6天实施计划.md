# 第5至6天实施计划：真实上传与公式保存

日期：2026-10-21。用户已授权按十五天计划完成 Day 5、6；使用 brainstorming 与 writing-plans 梳理，在当前工程顺序执行。文档使用中文名称，代码按认证、存储、图像处理、数据事务和页面职责分开。

## 设计与范围

1. 私有对象存储采用 Docker SeaweedFS 4.48，使用标准 S3 API。相比直接写 public/，文件不能绕开鉴权；相比要求云厂商账号，本机即可验收。AWS SDK 适配层允许未来更换兼容服务。只开放本机 S3 端口，密钥随机生成，不发布管理端口。
2. 上传接口一次接收一张 JPEG/PNG 的二进制内容，文件名放编码后的请求头；不增加多文件表单解析。按实际读取字节数限制 10MB，不仅检查 Content-Length。Sharp 验证真实格式、完整解码与 2000 万像素限制，校正 EXIF 方向、移除元数据，再保存规范化后的图片。
3. 文件先 PENDING，S3 写成功后 READY。失败补偿删除对象并标记 DELETED；数据库和对象存储不假装是一个分布式事务。上传请求键和内容哈希防止重试生成重复文件，冲突明确反馈。崩溃遗留的 PENDING 记录保留给后续修复，不自动误删。
4. 模拟识别使用已验证属于当前用户的 READY 文件。以用户请求键幂等，在一个事务创建已完成的模拟任务、公式档案和不可覆盖的第一版。继续明确标注 isMock，不宣称识别图片内容；本次不实现 Worker 和真实模型。
5. 新增受保护的账号公式详情与历史页面。原始图片经同源鉴权代理读取，刷新仍可显示；编辑使用预期版本 ID，冲突返回 409，保留草稿且不静默覆盖。
6. 原有访客演示与账号数据分开。登录后的上传走真实存储和数据库，访客可明确选择本机演示。分类、收藏和完整搜索仍归 Day 7，对话保存归 Day 8。
