# Query第二轮：写入生命周期与缓存一致性

按用户已批准三轮方案执行第二轮，延续main工作区，不提交或推送。采用既有Vue Query依赖，不增新库、不修改数据库。

方案选择：保留各组件手写busy会重复逻辑；全量乐观更新需要跨筛选分页回滚；采用受保护的useMutation统一生命周期、服务器成功后更新缓存。通用组合函数只负责单次执行锁、身份、取消和mutation状态；领域组合函数明确列出编辑、删除、收藏、分类请求。创建仍单独维护原幂等回执。

请求快照绑定已确认owner与AbortSignal，重复调用在发送前拒绝；retry=false、networkMode=always，不在离线后排队自动提交。换号/卸载中止请求，晚到响应不触发缓存/UI成功。mutation结果不持久化、gcTime=0；请求头的预期账号由后端真实会话校验，不能授权其他账号。

成功后统一通知公式/分类及旧首页/历史缓存；收藏更新当前owner所有已缓存列表中的已有条目，取消收藏移除收藏列表条目，再失效重新核对筛选成员；删除移除已缓存列表的对应条目。缓存请求失败不把已经成功的写入报告成保存失败。组件仅管理草稿/冲突/提示，不重复失效。编辑保留expectedVersionId/expectedTitle，手动创建保留同requestKey与body重放、未知结果保留回执。

测试覆盖同步双击、失败不重试、离线不排队、卸载/换号晚响应、按owner跨列表更新、创建回执恢复和明确拒绝清理。扩展隔离390px浏览器测试覆盖分类CRUD/分配、创建、删除、错误后重试与账号头拒绝，运行quality:quick及定向E2E。
