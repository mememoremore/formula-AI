# Query第三轮设计：回归与收尾

延续已批准的三轮方案，用户要求开始第三轮。审计Query读取/写入/账号边界及两轮遗留路径；不增加业务功能、不迁移聊天任务、不增库、不改数据库、不提交Git。保留有历史兼容/安全清理用途的旧key匹配，不强删保护断言。

修复已验证的诊断浮层遮挡：将DiagnosticCopy从app外部固定浮层移到默认布局main中内容后的普通文档流，保留复制/关闭与可访问状态；路由path变化清除旧页面提示。错误自动采集与TraceID不变。浏览器测试不再通过提前关闭提示绕开遮挡，而是在提示仍显示时点击保存/重试，验证进入另一页面后提示移除。

Query旅程扩展320/390/430/1440px，每个旅程/视口独立DB/S3环境以保留真实注册及OTP限流。沿用现有矩阵脚本，queries模式接入同一机制；默认浏览器矩阵补上从未被px筛选选中的解释渲染/可观测性场景。审查旧浏览器用例与当前OTP注册、强制登录、当前公式产品语义的一致性，只更新失效的交互步骤，不削弱并发/资源/导出断言。
