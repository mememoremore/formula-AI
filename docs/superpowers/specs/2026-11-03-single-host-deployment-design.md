# 4核4GB 单机部署设计（2026-11-03）

用户已确认单机 Docker、SeaweedFS、已有备案域名 www.ideal-formula.top 与 HTTPS 证书。

生产栈独立于本地 compose：Nginx 终止 TLS，Web 提供 Nuxt 生产服务，Worker 执行队列，PostgreSQL 和 SeaweedFS 使用独立命名卷，Python 只读加载外部模型。服务器已有 Nginx 占用80/443，复用宿主机 Nginx 和现有证书；仅 Web 映射 127.0.0.1:13000，数据库、存储、模型服务不映射主机端口。初次使用新库，不迁移或清理本机数据。已有备份、模型、kind 容器及卷不改动。

镜像在开发机构建，服务器只加载和运行。使用固定版本 Compose CLI 插件，不替换已有 Docker Engine。镜像包含现有 Prisma CLI（初始化与后续迁移）和 tsx（运行现有 Worker），不引入另一套任务执行器。Pandoc 使用已有验证版本及校验和。

启动分两阶段：先数据库和存储，执行既有迁移、队列初始化与存储检查；再启动 Web、Worker 与识别，最后核对并重载现有宿主 Nginx。初始化失败即停止启动，不重置数据库。生产显式使用 python/deepseek，SMTP 密钥只在忽略的环境文件；镜像不包含密钥、私钥或模型。日志限大小，不运行整套本地监控。孤儿图片先 report。

单机 Docker 内部 S3 地址仅允许显式启用的 http://storage:8333；其他远程地址仍要求 HTTPS。认证只在显式信任代理时读取 Nginx 覆盖的单个客户端 IP；Web 只映射回环端口，防止伪造头绕过限流。

验收：Compose 解析、生产镜像构建、独立项目数据库/存储/队列初始化、生产 HTTP 与 TLS 代理冒烟、模型在受限资源内加载及一次合成图片推理。资源限制是初始预算而非容量保证；本地测量不能替代腾讯云实例实测。服务器 Docker29.1.3/API1.52；80/443由现有Nginx监听。证书对应配置与DNS仍待核对。

资源验证：本机独立模型容器2核/1792MiB/禁用Swap，一次合成f(x)=x+1推理成功，耗时21307ms，cgroup内存峰值1487MiB，结束1234MiB，无OOM。仅代表单个样本，服务器和复杂图需再测。
