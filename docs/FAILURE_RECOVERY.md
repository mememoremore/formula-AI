# 失败恢复与安全清理

## 网络、刷新与切回前台

任务状态以数据库为准。任务页刷新读取已存在任务；online、pageshow及重新可见的visibilitychange触发一次去重的只读刷新。离线和页面隐藏时暂停轮询，暂时读失败保留最后成功快照，按2/4/8/16/30秒退避，成功后恢复正常频率。401/403/404不自动循环重试；用户重新登录或进入有效任务后再恢复。离开页面注销监听器并停止定时器。

聊天优先SSE快照，断开后有限重连并回退轮询；切回前台读取成功后恢复活动轮次的SSE连接。上述操作不会POST新任务或重新调用模型。手机系统杀死页面、关闭浏览器、清除会话存储不能保证未确认意图仍可恢复；已提交任务仍可从账号历史找回。原始未上传图片只在内存，刷新后可能需要重新选择。

## 三种“重试”

| 情况                 | 行为与额度                                             |
| -------------------- | ------------------------------------------------------ |
| 请求已提交但回执丢失 | 原requestKey确认原操作，不再创建或扣额                 |
| 后台暂时失败         | 同一任务的新attempt，由队列决定重试，项目额度不重复扣  |
| 用户点重新生成       | 最新失败文本回答的原问题作为新轮次，明确使用一次新额度 |

同内容但新requestKey是新操作，不按文本相同合并。内部额度一次不代表外部模型供应商绝不会重复计费；进程退出时供应商调用可能UNKNOWN，已有调用尝试审计保留这类不确定性。

失败回答旁的“重新生成（使用1次额度）”复用既有提交与会话回执，忙碌时不能重复点击。旧问题与未完成回答不删除，新问题单独保存；失败/停止片段不进入后续模型的完整历史。重新生成重新请求模型，不是从中断token续写。结构化解释首轮使用已有公式解释重新生成入口，不伪装成普通文本提问。

## 遗留图片闭环

Worker独立运行有界图片核对，每60秒最多50条，游标轮转避免前排已引用图片饿死后续项。模式通过FORMULA_RESOURCE_ORPHAN_MODE设置：off停用，report默认只读，apply执行受限清理。非法模式拒绝启动。关闭Worker会等待本轮核对结束，不留后台删除悬挂。

允许自动回收的范围只有：当前配置桶中数据库登记的IMAGE、上传已完成、无任何识别任务/导出/头像引用、无活动或不确定写入租约，且超过至少24小时宽限期（配置更长时沿用更长值）。即使引用任务已失败也保留其输入图，供用户重新识别。PENDING、未知对象、头像、DOCX、模型和备份不进入此自动范围。

删除前在资源锁内复查引用并记录DELETING与独立持久审计，识别提交使用同一资源锁，不能在删除后引用图片。网络I/O不持有资源锁。删除后必须HEAD确认对象缺失，才能落账DELETED；响应丢失、HEAD失败或数据库写入失败保留状态和计量。只有匹配当前对象指纹的DELETE/STARTED审计才允许后台重试DELETING，不凭年龄处理未知写入。重复执行不重复创建业务结果。

本机核对（默认只读，不需要打开Grafana）：

```powershell
npm run storage:audit
```

报告仅含文件/租约编号、对象指纹和分类，不输出对象路径或凭据。单文件报告可追加 --file=文件UUID；只有显式追加 --apply 和 --bucket=当前桶名，并通过上述图片安全条件，才可执行该文件清理。此运维命令仅允许本机数据库与存储。批量apply由受控Worker模式执行，不能用命令行笼统删除整个桶。

查看后台核对日志：

```logql
{service="formula-worker"} | json | operation = "orphan-cleanup"
```

reviewed/deleted/kept是本轮观察计数；不等于整个桶的对象总量。未知/PENDING问题继续由独立租约核对标记REVIEW_REQUIRED，需要结合生产者是否仍活跃等事实人工核对，不自动释放未知占用。

## 测试与范围

故障浏览器测试使用真实HTTP、账号、数据库和队列，模型边界为受控替身；覆盖Worker退出、断网、重新生成、回执丢失、前台事件恢复，验证任务数量、旧片段和项目额度。前台恢复用浏览器visibility事件模拟，不等于真机系统杀进程测试。资源测试使用隔离数据库和S3，覆盖引用、宽限期、PENDING、DOCX、删除响应丢失、重复核对与调度停止。

验证入口与隔离规则见 [测试指南](TESTING.md)。
