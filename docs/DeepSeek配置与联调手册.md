# DeepSeek 配置与联调手册

实现说明及验收边界见 [第12至13天开发说明与验收记录](第12至13天开发说明与验收记录.md)。本项目使用固定版本 `@langchain/deepseek 1.1.18`、`@langchain/core 1.2.20`，只在后端适配器中使用，不引入Agent、工具、向量库或知识库。

## 启用真实回答

最新状态：2026-10-21已由用户配置本地密钥，重启后完成一次真实调用，见 [DeepSeek真实联调记录](DeepSeek真实联调记录.md)。下方保留配置与排查步骤。

在项目根目录本地 `.env` 中配置，密钥不要粘贴到聊天、页面或提交进仓库：

```dotenv
NUXT_AI_PROVIDER=deepseek
NUXT_AI_API_KEY=填写你自己的DeepSeek密钥
NUXT_AI_MODEL=deepseek-flash
NUXT_AI_BASE_URL=https://api.deepseek.com
```

这里的模型名和服务地址依据当前 [DeepSeek官方调用文档](https://api-docs.deepseek.com/)；如账户可用模型发生变化，修改私有模型配置。API密钥从 [DeepSeek平台](https://platform.deepseek.com/)创建。填写后确认账户具备调用条件，再同时重启Nuxt与Worker，避免网页配置和Worker不一致。

```powershell
# 终端一
npm run dev

# 终端二
npm run worker
```

开发启动与数据库/存储准备步骤见 [后台任务与导出操作手册](后台任务与导出操作手册.md)。生产构建仍需另启包含源码、运行依赖和tsx的Worker；完整部署包装按第14天完成，`.output`本身不包含独立Worker。

启用后登录，从公式详情选择“AI解析这个版本”，开始对话前页面会说明公式和历史将发送给DeepSeek。回答会标注来源；模拟识别出的公式仍然只是固定样例，AI解释不会把图片识别自动变成真实功能。

## 模拟与缺少配置时的行为

`NUXT_AI_PROVIDER=mock` 为明确模拟模式，不需要模型密钥。当前本机已配置DeepSeek并启用真实账号回答；需要演示时可显式切回mock并重启。访客的本机演示接口始终为模拟，与账号服务分开。

当类型为`deepseek`但密钥为空时，新对话按钮显示未配置提示；已有对话提交问题返回503，不创建任务或扣额。Worker遇到此配置同样明确失败，不回退模拟。不要通过把空密钥替换成示例字符串来判断真实接通。

## 流式、刷新与停止

任务在Worker运行，片段保存在PostgreSQL；SSE订阅只负责读取。关闭页面不会取消任务，刷新可继续查看。订阅断开时回退轮询，必要时手动重新读取；SSE最长约60秒，同一轮不会无限自动重连。

点击“停止生成”保存已收到的片段并标记未完成，停止不返还已经接受的应用额度。Worker会中断上游读取，但供应商可能已经产生计算费用。新提问属于新请求，使用新额度；网络响应丢失后用原问题重试会复用原请求键。

应用默认对话每日30轮，北京时间08:00重置，可由`NUXT_CHAT_DAILY_LIMIT`调整。每轮最多3次队列尝试；这与供应商Token和金额账单是两套统计。当前输出上限2048 tokens、正文16000字符、单次调用60秒，不启用思考内容展示。

## 常见故障

| 表现                 | 处理方法                                                                    |
| -------------------- | --------------------------------------------------------------------------- |
| 一直排队             | 检查数据库、队列安装及独立Worker是否已启动                                  |
| 配置或账户不可用     | 核对私有密钥、模型和账户状态；401/402/403/404不自动重试                     |
| 限流或服务暂时不可用 | 429或临时故障由队列有限重试；不要额外叠加SDK重试                            |
| 回答未完整生成       | 可能达到长度预算、响应被截断或无正文；缩小问题范围后重新提交                |
| 实时连接已断开       | 页面退回轮询；线上部署检查代理缓冲和超时，当前已发送`X-Accel-Buffering: no` |
| 修改配置后仍是原模式 | 同时重启Nuxt和Worker，确认两个进程使用同一环境配置                          |

错误映射参考 [DeepSeek错误码](https://api-docs.deepseek.com/quick_start/error_codes/)，流式接口参考 [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。供应商原始错误、请求头和思考字段不会转发到页面。
