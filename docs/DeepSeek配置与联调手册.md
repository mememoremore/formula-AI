# DeepSeek 配置与联调

## 作用与私有配置

Python 负责图片转 LaTeX，DeepSeek 负责公式解释和连续追问，两者独立。浏览器只调用本项目 API；供应商 Key 由服务端和 Worker 持有，不进入客户端配置。

| 配置             | 含义                           |
| ---------------- | ------------------------------ |
| NUXT_AI_PROVIDER | mock 或 deepseek，明确选择来源 |
| NUXT_AI_API_KEY  | 服务端供应商凭据               |
| NUXT_AI_MODEL    | 账号可用的模型名称             |
| NUXT_AI_BASE_URL | API 基础地址                   |

项目代码的模型回退值为 deepseek-flash，基础地址默认 https://api.deepseek.com；模型是否可用应以你的供应商账号实际权限为准，配置名称不是可用性保证。不要把网页登录密码填成 API Key。

修改配置后重启 Nuxt 和 Worker。选择 deepseek 但配置不完整时应明确失败，不自动以 mock 结果冒充真实成功。不要把真实 Key 写进 README、截图、测试 fixture 或 Git。

## 调用和输出校验

LangChain TS 适配器负责调用供应商。普通回答流式写入持久化快照；结构化解释包含概要、符号、条件、步骤、例子和注意事项，由共享 Zod schema 严格验证，再进行数学片段渲染检查。

输出结构合法不代表数学结论正确。页面不展示供应商内部模型名来代替质量说明，也不要求用户选择 v1/v2。解释和会话在后台绑定当时的公式内容，保证上下文一致。

上下文只使用完整成功轮次，按完整问答裁剪。失败和停止的文本保留展示；重新生成是一次新调用，不能保证从中断位置续写。

## 联调步骤

1. 先确认账号、数据库、存储与 Worker 正常。
2. 显式选择 deepseek 并配置自己的 Key、可用模型。
3. 在已登录页面创建公式，发起解释或提问。
4. 查看任务状态、流式展示与刷新回读。
5. 到 Grafana 用同一 trace 查询 API、队列与供应商调用记录；不要通过打印原始问题或密钥排查。

真实联调会消耗供应商额度。日常单元、协议和浏览器测试使用受控替身，不能据此宣称真实供应商已验证。切换回 mock 应同样显式配置并重启 Worker。

## 常见问题

| 现象               | 检查                                           |
| ------------------ | ---------------------------------------------- |
| 配置不可用         | 提供方、Key、模型权限、基础地址和进程重启      |
| HTTP 鉴权/配额失败 | 供应商账号状态与错误分类，避免无意义重试       |
| 超时或中断         | 网络、执行时限、调用尝试与队列执行权           |
| 内容保存失败       | 结构、长度、数学渲染或任务状态是否已改变       |
| 重试后计费疑问     | 项目幂等只约束内部额度；外部调用可能结果不确定 |
