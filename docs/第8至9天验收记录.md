## Microsoft Word 的实际验收

使用官方 Pandoc 3.12.1，通过真实转换器生成以下 DOCX，每份均满足：有一个原生 OfficeMath，没有公式图片，正文包含版本和 LaTeX；Microsoft Word 可打开并输出一页 PDF。

| 样例                           | 结构证据                                   |
| ------------------------------ | ------------------------------------------ |
| 分式及二次方程                 | OMML `m:f`，同时含根式和上下标             |
| 根式                           | OMML `m:rad`                               |
| 定积分                         | OMML `m:nary` 和分式                       |
| 上下标                         | OMML `m:sSubSup`                           |
| 二阶矩阵                       | OMML `m:m`，Word 中为原生矩阵              |
| 含特殊符号和类似图片语法的标题 | 保留为纯文字，不下载外部图片或注入文档结构 |

在分式副本中，实际把公式字符改为 `y`，保存、关闭、重新用 Word 打开，仍有一个原生 OfficeMath，保存后的 OMML 确认包含修改字符。并非只根据 ZIP 内出现某个字符串判断可编辑。

标准 `render_docx.py` 需要 LibreOffice，本机未安装，因此改用实际目标 Microsoft Word 导出 PDF，再通过运行时自带 PDFium 生成 PNG。六份一页文档均已逐页查看：数学结构、中文、标题和源码无缺字、裁切或重叠。Word 结构与页数记录位于 `artifacts/day89-docx/word-verification.json`。

本机未找到 WPS，**WPS兼容性未实测**；不将 Word 结果直接当作 WPS 验收。

## 生产浏览器流程

独立 Playwright 会话完成：

1. 注册临时账号，上传真实 PNG；Worker 停止时看到排队，刷新后任务仍在。
2. 启动独立 Worker，原任务自动完成，页面进入已保存公式详情。
3. 编辑为矩阵 v2，创建绑定 v2 的账号对话，发送问题和连续追问；刷新后两轮四条消息仍保留。
4. 对话列表能重新打开记录，输入框点击后没有外框。
5. 从详情提交 v2 Word，页面轮询到完成；刷新后仍能下载，浏览器实际保存 DOCX。
6. 校验下载文件确有原生矩阵和 v2 内容。之后将公式改为 v3，旧对话仍显示 v2，已经下载的文档内容未变化。
7. 检查390px手机页面，以及320px和1280px宽度下无页面横向溢出。
8. 退出后对话页面要求登录，匿名读取原下载链接返回401。

流程中页面异常为0；匿名下载检查主动产生的一条401网络错误为预期权限拒绝，不算业务失败。最后一条回复相对固定输入栏的位置复核结果为 `lastReplyVisible: true`。相关脚本保留在 `artifacts/day89-browser-setup.js` 与 `artifacts/day89-browser-check.js`。

## 实现过程中补齐的边界

- Pandoc 二进制输出显式使用 `--output=-`；转换警告即失败，避免悄悄产出缺失公式的文档。
- 不让标题触发语言模板或外部资源读取，A4 和中文字体直接在输出样式中规范。
- 进程超时作为可有限重试的故障；不支持的公式作为明确终态失败。
- 额度只在任务与入队共同提交时计数；网络重放、自动重试不重复扣额。
- 对话轮次中断会持久化失败记录并允许后续提问，防止永久卡在“处理中”。
- 自动滚动给输入栏留出底部空间，避免最后一条回复被固定输入栏遮挡。
