# R3 全局布局、导航与响应式基础

日期：2026-10-26。R2 基线 `e15af3b`，分支 `refactor/r3-layout-navigation`。不进入 R4。

## 1. 范围与现状核对

已阅读《Formula重构.md》、R1/R2 验收说明、当前布局/Token/公共组件/导航/路由、中间件及 17 页元信息。仓库没有独立命名的 R0 盘点报告文件；未声称读过不存在的文件，本轮以会话 R0 要求和当前源码交叉核对。

本轮没有修改 `app/pages` 中的业务页面、API、Prisma、Worker、权限/额度/事务、依赖、锁文件、Nuxt 主配置或 R2 颜色/字体 Token。没有创建第二套导航，也没有把所有页面拓宽。

## 2. 容器规则

| 模式            | 900px 以下             | 900px 起    | 后续适用场景                       |
| --------------- | ---------------------- | ----------- | ---------------------------------- |
| compact（默认） | 最大 480px、视口内居中 | 最大 480px  | 登录、表单、设置、未逐页改造的页面 |
| reading         | 最大 480px、视口内居中 | 最大 760px  | 帮助、说明、公式阅读               |
| workspace       | 最大 480px、视口内居中 | 最大 1080px | 公式库、编辑、聊天工作区           |

900px 延续 R2 宽布局样板断点，在 768px 平板暂不强行展开。760px 为阅读上限；1080px 沿用 R2 样板。宽模式不自动建立多列，业务页应在自己的轮次决定内容组织。

```ts
definePageMeta({ contentWidth: 'reading' })
// 或 contentWidth: 'workspace'；未声明或无效值均回到 compact。
```

`app/types/page-meta.d.ts` 提供类型；`app/utils/layout.ts` 只归一化元信息；default 布局和 AppBottomNav 接收同一模式。CSS 统一负责尺寸。Teleport 后的导航显式带宽度模式，不依赖已经断开的祖先继承。

页面顶/底和左右内边距计入 safe-area。已有 28px 顶部、24/18px 水平间距及 480px 默认值保留。长公式保持内部滚动，没有全局 `overflow-x:hidden` 或强制缩小公式。

## 3. 导航、滚动与公共浮层

- 原四个主入口、fixed、Teleport、活动项和旧地址兼容均保留。
- 再次点击当前主入口，保留完整筛选与锚点；跨入口只传递合法的显式 demo/account 空间，不带搜索词或版本参数。
- URL fragment 不会发送给 SSR。导航挂载前统一省略 fragment，挂载后恢复，以免带锚点的旧地址出现 href 水合差异。
- 同页参数变化继承已有返回来源，避免详情的版本/筛选地址变成自己的“父页面”。登录、新对话、识别中转仍继承可信来源。
- 返回来源优先级：内存来源 → 经过白名单校验的浏览器上一项 → 页面已有 fallback。外站、同页及中转页不能成为返回目标。浏览器历史在挂载后读取，避免首帧水合差异；刷新后可以保留列表查询上下文。
- 浏览器前后退的 saved position 优先于同页查询规则。普通查询更新不强制滚动。离开前由 router.beforeEach 记录快照，避免短新页渲染后旧位置已被截断；快照最多 100 项，按完整地址隔离。
- 新插件只注册路由守卫，应用卸载时注销；不增加 window scroll/resize 监听。原聊天自动滚动保持原实现，R8 再处理。
- 底部导航是否存在决定公共占位。Toast 叠加导航、输入区高度与安全区；无导航页不再空出 80px。ChatComposer 保留原行为，宽度继承布局，必要时放在导航上方；卸载后现有 ResizeObserver 和高度变量清理已检查。
- AppModal 继续使用原生 dialog 顶层与焦点机制；打开时公共 CSS 锁定根滚动，内容自身可滚动并阻止滚动链。关闭或卸载 dialog 后 CSS 锁自动解除。
- PageHeader 保留原返回行为，补齐修饰键点击的浏览器默认语义；主内容可被“跳到主要内容”聚焦。

## 5. 公共装饰溢出与剩余页面问题

55 组实际公开页面观察发现：原 PaperArtwork compact 把画布改为 120×115，却保留按 220×210 定位的纸张和铅笔，再缩放 0.63；PageIntro 又向右偏移，造成 AI、上传、帮助、反馈页面小屏溢出。

本轮只修正公共缩略模式：保留完整 220×210 画布再缩放 0.5，放入右对齐的 110×105 容器。完整插画模式、公式数据和业务逻辑不变。复查这四页在 320/390px 均不再整页横向溢出。

剩余**已观察、未修复**的局部问题：

| 页面   | 320px 时 scrollWidth | 390px 时 scrollWidth | 源码原因与归属                             |
| ------ | -------------------- | -------------------- | ------------------------------------------ |
| 首页   | 335px                | 399px                | home-hero 的负边距与 hero-art 负 right，R4 |
| 公式库 | 327px                | 391px                | library-hero 装饰图负 right，R5            |

两页源码本轮未改变。没有用全局裁切掩盖这些问题，也没有把它们计入“全站无溢出通过”。未来逐页修复应限定装饰绘制区域，不裁掉真实公式或交互控件。

## 7. 验证环境与复演

复用 R1/R2 的安全机制。`npm run preview:design` 使用空 dotenv、干净环境和 mock 模型，不读取开发凭据、不启动数据库或 Worker。测试层新增的空会话中间件只处理 `/api/account/session`，避免真实页面 SSR 触及认证资源。登录写请求仅在浏览器被拦截，返回固定成功响应；没有创建账号、保存 Cookie 或写数据库。

```powershell
npm run check:assets
npm run typecheck
npm run typecheck:design
npm run test:unit
npm run check:build
npm run preview:design
playwright-cli -s=formula-r3 open http://127.0.0.1:3200/__layout
playwright-cli -s=formula-r3 run-code --filename=tests/design-preview/check-layout-browser.js
playwright-cli -s=formula-r3 run-code --filename=tests/design-preview/check-public-pages-browser.js
```

类型检查会生成框架文件；先完成类型检查再启动/重启预览并运行浏览器，避免预览构建目录热更新影响验收。浏览器脚本依赖本机已有 playwright-cli；CLI 输出 `### Error` 时即为失败，不能只看进程退出码。

截图目录：`docs/设计稿/R3布局导航`。手机 320/390、桌面工作区、长页末尾、弹窗、输入区和真实首页均为 Chromium 页面截图。真实首页截图也如实保留上述待 R4 修复的问题。安全区测试使用 CSS 变量模拟 28px 顶部、34px 底部，不等于真机刘海或软键盘验收。
