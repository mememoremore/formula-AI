## 执行批次

- [x] 安全守卫：纯配置校验、冲突拒绝、Docker 身份核对、API 身份核对、测试网络限制。先运行无外部依赖的拒绝测试。
- [x] 独立环境：单独 Compose，独立随机运行标识与凭据，专用端口和 tmpfs；只在核对容器身份后初始化空测试数据库/队列。测试专用 Nuxt 层不改变生产路由。
- [x] 测试迁移：所有集成测试入口和崩溃子进程先验证环境，不加载开发 `.env`；workspace 测试真实保留 202，并由受控 Worker 执行后核对结果。
- [x] 质量基线：测试类型覆盖、命令分类、静态资源存在性检查、客户端产物扫描与中文执行说明。实际构建仍被原有三项缺失素材阻断，不能宣称通过。
- [x] 检查各批 Diff；运行适用的安全检查，记录失败、跳过和未执行项；完成 R1 后停止。

## 安全边界

不修改页面、生产 API、Schema、事务、幂等或执行权逻辑；不连接开发资源，不调用付费模型，不执行清库或破坏性迁移。专用测试数据库允许在身份核对后应用既有迁移，不改变迁移内容。

拒绝测试以注入的核对函数和受控本地服务验证缺失、冲突、伪造身份与非本地目标；不得通过实际连接开发资源验证拒绝行为。

## 验收

错误配置在资源访问前失败；测试 API、Worker 与测试进程的运行标识和配置指纹相同；清理只能处理本次隔离环境。保留原有效断言，不把 202 转成伪造的 200。Docker 不可用时不能启动集成测试，也不能将未执行报告为通过。
