# 第12至13天实施计划

用户已确认暂缓第11天、接入 DeepSeek，并采用 LangChain TS。本轮在现有工程中逐项执行，中文文档与代码可读性优先。方案来自已确认的阶段计划，不重新要求流程审批。

## 范围与设计

第12天先交付通用推理错误分类、超时和取消信号、有限重试与故障验收。Python真实识别、预处理和实际图片回归依赖第11天，明确保留未完成。

第13天使用固定版本 `@langchain/deepseek` 与 `@langchain/core`，独立 ChatAdapter 隔离调用库。默认继续显式模拟模式；设置 `NUXT_AI_PROVIDER=deepseek` 才启用真实调用，缺少密钥明确失败，绝不退回模拟。官方模型名核对为 `deepseek-flash`，可私有配置覆盖；当前不启用思考输出、工具、搜索或图片输入。

保留“提交任务 → 独立 Worker → 数据库”的架构。Worker按有界间隔保存部分回答；受保护的 SSE 只读取本人对话快照，不启动新模型调用。刷新重新读取数据库即可恢复，SSE断开退回既有轮询。页面断开不取消后台任务，用户可显式停止当前轮次。成功回答、失败片段及来源均有标记，不把未完成片段当作完整答案。

流式中间结果的写入与队列执行权同事务验证，失效 Worker 不得覆盖新尝试；每次重试清空本次部分内容。LangChain/底层 HTTP 自动重试关闭，只有 pg-boss负责最多3次任务执行，避免重试叠加。每次调用最长60秒，低于90秒队列执行期限；正文和历史有字符预算。
