# R6.1 公式标题并发修复与验收说明

日期：2026-10-27。基线 R6 `e308c40250603cfa3dc93c6504f3e788bfb85226`；分支 `fix/r6-1-title-concurrency`。独立补丁，完成后停止，不进入 R7。

## 1. 修复结果与原子性

账号版本保存现在必须携带 `expectedTitle + expectedVersionId`。原标题来自**打开编辑器时的快照**，不能用正在填写的新标题代替。

`server/database/formulas.ts` 的 `appendFormulaVersion` 在同一个既有 Serializable 事务中读取所属公式和最新版本、比较原标题与版本 ID、执行标题更新或追加内容版本。任一不匹配抛出原有 VERSION_CONFLICT，HTTP 仍映射为 409。

即使两个事务最初都读到相同旧状态，也不能都提交对该公式的竞争更新。既有序列化/版本号冲突处理会重试整个事务，重试时必须重新读取并比较**两个**预期值，败方返回 409；不是在事务外 GET 后再盲写。混合竞争中，失败事务创建过的版本也随事务回滚。

未改变事务隔离级别、原有最多三次数据库冲突重试、所有者限制、不可变版本、唯一版本号、原图、分类/收藏和固定 AI/导出引用。无 Schema 修改或新迁移。

## 2. HTTP 与旧请求兼容规则

```json
{
  "title": "准备保存的新标题",
  "latex": "x=2",
  "expectedTitle": "打开编辑时读到的原标题",
  "expectedVersionId": "打开编辑时读到的版本 UUID"
}
```

| 情况                                           | 处理                              |
| ---------------------------------------------- | --------------------------------- |
| 合法名称/内容且快照匹配                        | 200，返回 SavedFormula            |
| 原标题或内容版本已过期                         | 409，不发生部分写入               |
| 缺少 expectedTitle 的旧请求                    | 400，明确提示刷新页面重新编辑     |
| expectedTitle 为 null、数字、空白或超过 100 字 | 400，不写入                       |
| 未登录                                         | 401                               |
| 外部账号资源/不存在资源                        | 404，仍先检查归属，不泄露资源详情 |

没有推断当前标题来填补旧字段，也没有不受保护的兼容分支。内部 `AppendVersionInput` 同样要求 expectedTitle，运行时也拒绝缺失值；既有直接调用测试均更新为传入真实快照。

这是有意收紧的写入契约：新旧读取 DTO 不变，旧写客户端需升级。前后端应配套发布，旧标签页先保留草稿再刷新。只升级前端、继续运行旧后端不能视为保护生效。

### 重复提交语义

版本保存原本没有 requestKey，本次没有虚构新的幂等协议：

- 内容保存成功后，用原版本 ID 重放返回 409，不追加第二个版本。
- 标题保存成功后，用原标题重放返回 409，不再次修改标题/时间。
- 两个完全相同的变更请求竞争，结果为一个 200、一个 409。
- 标题和正文均未改变的真实 no-op 可重复 200，不增加版本。

其他上传、识别、聊天、导出请求键和任务处理不改。超时后结果不确定时应重新读取，不自动重放旧草稿。

## 3. 客户端草稿恢复

AccountFormulaEditor 提交 original.title。409 后保留名称和 LaTeX，显示冲突提示并禁用直接重放旧草稿。

- “复制当前草稿”包含名称与 LaTeX；复制不可用时仍保留编辑框并提示手动保留。
- “重新读取最新内容”复用 R6 的放弃确认；取消则不改变草稿。
- 用户同意后才读取当前公式；读取失败仍保留草稿和冲突状态，可重试。
- 读取成功才用最新内容重建快照并更新详情，不自动合并旧草稿，也不伪装成保存成功。
- 保存与读取共用单一 operation 状态，busy 由它派生；期间禁止冲突操作，离页取消请求，旧响应不更新已卸载组件。

没有改 R2—R5 的样式/页面。仅在 R6 编辑弹窗增加必要恢复动作，复用既有组件和 class。

真实浏览器截图：[冲突保留草稿](设计稿/R6.1标题并发/冲突保留草稿390.png)、[读取最新内容](设计稿/R6.1标题并发/读取最新内容390.png)。账号数据来自明确隔离的内存替身，不冒称真实后端浏览器联调。

## 4. 测试证据

先修改正确性断言，旧服务在 R1 新环境中得到 **21 项：16 通过、5 失败**，失败包括原 R6 覆盖复现、双标题竞争、标题/正文竞争、重复提交和缺字段旧请求。这证明新增断言可以捕获原缺陷。

修复后，原 R6“允许覆盖”的现状测试已改为：A 改名 200、版本不变；B 使用旧快照改正文 409；A 的新名和原正文均保留。没有保留认可覆盖行为的通过测试。

| 验证                | 最终证据                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------- |
| 两窗口改成不同标题  | 8 组真实 HTTP 并发，每组 [200,409]；只有胜者标题，仍一个版本                              |
| 标题与正文竞争      | 8 组真实 HTTP 并发，每组 [200,409]；无失败方部分写入                                      |
| 同请求并发/顺序重放 | 标题、正文分别验证 [200,409]；再次重放 409，no-op 重放 200                                |
| 仅内容版本过期      | 保留原数据库与 HTTP 内容冲突断言                                                          |
| 新旧请求及权限      | 缺失/非法原标题 400，错误原标题 409；外部 404、未登录 401；原记录不变                     |

真实并发测试通过 Promise.all 发出请求，不是只测试两个顺序调用。16 组并发是有限回归证据，不是高负载压力认证。

首轮新增夹具挤出旧历史分页窗口，未放宽原断言，而是在对应测试结束后仅清理本用例 UUID。浏览器复制断言发现 Windows 剪贴板将 LF 转为 CRLF，按换行规范化后继续严格核对完整名称和 LaTeX；恢复检查等待实际字段回填，不以提前满足的 networkidle 代替成功。

## 7. 剩余边界、发布与回滚

此方案比较当前标题值，不是全局元数据修订号：标题从 A 改为 B 再改回 A、内容版本也未变时，持有 A 的快照可以继续保存，因为当前预期值一致；不宣称检测所有历史变更。若产品要求检测 ABA，需要另批独立修订号。分类等元数据不纳入本次冲突范围。

没有新增请求键或草稿持久化。保存超时仍可能已经提交，复制受浏览器权限限制，浏览器崩溃恢复不在本补丁范围。数据库连接故障/极端争用耗尽原重试仍可能失败，不把一般基础设施错误伪装成标题冲突。

独立本地 Commit 的 Hash 在会话交付，不推送。需要回滚可经确认 git revert <R6.1提交>，但整体回滚会重新引入原标题覆盖风险及旧契约；不能把回滚后的状态视为仍具备本补丁保护。

没有新增依赖、Schema 或状态框架；所有新保护均位于原保存边界。R6.1 完成后等待评审，不自动进入 R7。
