## 4. 编辑与草稿

打开时复制名称、LaTeX、预期版本 ID；Dirty 与该快照比较，不跟着外部 props 漂移。首尾空白归一化，无实际修改不保存、不确认。游客额外比较分类。

两类编辑使用同一 canLeave：未改直接离开；有草稿确认放弃；保存中拒绝关闭和路由离开。beforeunload 请求浏览器原生保护；卸载移除监听。没有把账号草稿写入 localStorage。

名称/长度和 KaTeX 预览反馈在保存前提供；安全参数与 MathFormula 对齐。非法或无法支持的 LaTeX 先修正再保存；原有读取仍可展示旧数据的错误回退。未改内容不能重复新建版本。

账号保存失败保留草稿；409 给出专门冲突提示，不自动重放旧正文、不静默替换草稿。成功回填服务端 DTO，再关闭；保存按钮及输入有 busy 限制。取消 HTTP 不等于撤销服务端已接受的写入，不自动重试不确定结果。

浏览器脚本为稳定统计，将 confirm 替换为可控制的同意/拒绝函数，测试 SPA 后退与草稿保留；beforeunload 通过可取消事件验证。另在没有替换 confirm 的独立浏览器实际触发原生确认：取消后文本仍为“未保存的原生确认测试”，确认放弃后打开的 dialog 数量为 0。调试中也实际观察到整页离开的原生 beforeunload 提示；未宣称操作系统提示样式或真机行为已全面验收。

## 5. 版本、收藏、分类和导出

- 服务端不可变版本与 Serializable 事务原样保留。正文变化追加，只有名称变化不新建内容版本。
- 历史版本展示真实 origin 标签，固定版本 ID 传给 AI 入口。游客版本标注为本机内容，不伪装为账号持久化。
- 收藏复用 useAccountFavorite，不做提前乐观写入；busy 防重复，失败保留原状态。分类保留 AccountCategoryPicker 原规则和重试。
- 编辑、分类及收藏结果更新当前详情，失效原有列表缓存；浏览器验证返回保留 space/q，并显示新标题、正文、分类与收藏。没有进行 R11 全站缓存重写。
- 导出显示所选版本的已保存公式，不能读取编辑器草稿。失败反馈留在导出弹窗，不将详情变为失败页。重试保留相同 requestKey 和版本，换版本生成新的 key；原异步任务/Worker 不改。

## 6. 标题并发缺口：真实复现，待批准

证据：server/database/formulas.ts 的 appendFormulaVersion 只检查 expectedVersionId；相同 latex 分支只更新标题，不推进内容版本。API versions.post.ts 要求 title、latex、expectedVersionId，没有元数据比较条件。

新增 tests/workspace.test.ts 中“R6 已知契约缺口”测试在本轮全新临时 PostgreSQL + 真实 Nuxt API 中执行：

1. 两窗口读取相同快照 S。
2. A 仅改标题，返回 200，最新版本 ID 仍为 S.versionId。
3. B 用 S 中旧标题和新正文提交，仍返回 200，A 的标题被覆盖回旧值。
4. 旧正文版本仍完整保留，新正文变成第二版。

这是可重复的两个并发编辑窗口的有序交错，不冒称是随机同时提交压力测试。测试断言当前错误行为，是缺陷复现证据，不是认可覆盖行为；批准修复后必须改为 409 且保留 A 标题的正确性断言。原正文并发测试仍严格验证 [200,409]，没有放宽。

建议最小方案：请求增加 required expectedTitle（打开时原标题），appendFormulaVersion 在同一 Serializable 事务中同时比较 expectedVersionId 和原标题，不一致返回 409。无需 Schema 迁移，专门防止当前标题覆盖；标题改回同值不视为冲突。需要批准输入契约及旧客户端兼容策略，不能靠客户端保存前 GET 消除事务竞态。

另一方案是独立 metadataRevision 整数 CAS，能准确表达所有元数据修改，但需要 Schema/迁移与其他写入口同步，超出 R6。现有 updatedAt 精度为毫秒且分类也可能更新它，直接把它当唯一修订号会增加无关冲突，不能未经评估当作完全可靠替代。

本轮没有实施上述方案，也没有伪造“标题冲突已解决”。

## 10. 风险、评审与后续

标题覆盖仍然存在，需独立批准修复；不要把本轮提交描述为所有并发风险均消除。保存请求超时仍可能已被服务端接受，草稿保留但用户需核对最新版本，不自动重试。账号草稿有离开保护但不保证浏览器崩溃后恢复；游客浏览器存储失败仍沿用原提示机制。

全部版本仍由现有详情接口读取；数量增长后再评估分页，不为当前规模重写版本系统。缓存失效的全站统一归 R11，本轮不复制到聊天/上传。没有引入新的依赖、状态管理或数据库技术债务；新增的纯展示与局部 Composable 均有明确使用方。已知缺口和复现测试在后续修复时必须同步收敛。

提交范围仅本轮列出的文件，Hash 见会话最终交付。回滚经确认执行 git revert <R6提交>，不 reset --hard，不删除用户资源，不推送远程。

R7 建议先按 320/390/430 整理上传选择/预览/提交/识别状态，复用本轮公式阅读和错误规范；沿用 R1 隔离环境，明确失败重试与未确定结果，逐步衔接 R5 历史缓存前缀，不改变 Worker 终态和额度事务。
