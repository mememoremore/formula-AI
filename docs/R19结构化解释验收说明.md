# R19 结构化解释验收说明

基线：远端 main 的 R18 合并提交 f6cf8f8320d951004d316c3e588b7bdc2423c5fe。开发分支 feature/r19-structured-explanation，沿用安全克隆，不引入旧原始历史。

## 实现范围与职责

- 公式详情增加结构化解释入口、版本选择、全部版本历史和游标加载。每次明确重新生成建立新的解释会话，旧解释与追问保留。
- Conversation、ChatTurn、ChatMessage 承担解释状态与结果；复用既有 chat 队列、Worker、ChatCallAttempt、CHAT 额度、取消和异常恢复，不增加第二套AI任务系统。
- shared/explanation.ts：唯一结构契约、字段/条数/总长/数学渲染校验和确定性兼容文本转换。
- server/database/explanations.ts：解释提交、账号幂等、Serializable冲突有限重试、额度与入队事务，以及历史分页。
- server/database/explanation-queries.ts：不依赖最近消息窗口的基础解释查询，避免循环依赖。
- server/database/conversations.ts、chat-history.ts：一致快照、普通追问准入和成功历史规则。
- server/chat/prompt.ts、deepseek-adapter.ts：明确解释/追问模式与固定Prompt版本，显式json_object，不启用库内自动重试或自动JSON修复。
- server/worker/chat.ts：保留原执行围栏，仅扩展输入模式与完整结果校验；未验证JSON不写流式片段。
- app/utils/chat-state.ts：新结果加入运行时校验、同revision比较和不可变结果保护。
- AccountFormulaExplanations、FormulaExplanationContent、AccountChat：局部业务入口、结构展示与既有聊天交互，不重做全站视觉。
- explanation-intent、account-boundary：有界账号回执，提交前存储，超时/丢响应原键恢复，退出清除；不覆盖其他公式尚待确认的请求。

## 数据库与迁移

prisma/migrations/202610290002_structured_explanations/migration.sql 为 BEGIN/COMMIT 内的加法迁移：

- Conversation.purpose 默认 CHAT，新解释为 EXPLANATION，后者必须有固定公式版本。
- ChatTurn.responseKind 默认 TEXT，结构解释为 FORMULA_EXPLANATION；增加可空 promptVersion、requestHash。
- ChatMessage.structuredContent 为可空JSONB，非空限定成功AI消息和schemaVersion=1。业务层还执行完整结构校验。
- 解释历史复合索引，以及每会话仅一份基础解释的部分唯一索引。
- 固定会话purpose、轮次请求元数据与结构化成功消息的不可变触发器。
- 原数据保持普通聊天/文本/null，不解析或回填旧模型回答；固定FormulaVersion和原额度、队列表均未修改。

迁移只在R1新建的独立PostgreSQL执行；没有操作开发或生产数据库。新增测试使用随机私有schema复原旧表数据、执行同份迁移SQL并验证旧数据与回滚，不把小样本验证等同于生产大表锁评估。

## 事务与幂等

POST /api/account/formulas/:id/explanations 接受 versionId/requestKey，鉴权和CSRF后验证账号与公式版本归属。可选x-account-id仅用于拒绝迟到的跨账号提交，不能指定所有者。

首次请求在同一事务中创建解释会话、首轮和USER消息，预留一次CHAT额度，使用现有pg-boss事务适配入队并递增revision。账号请求键冲突事务回滚，再读取胜出任务；同键异文409，幂等重放优先于新增额度判断。请求摘要不包含当前服务器模板版本，已接受任务保存自己的promptVersion，部署更新不影响原请求重放。

新接口返回202及conversationId/task。GET同路径按versionId/cursor分页。查看与追问复用原conversation API，普通聊天默认文本，旧接口契约不变。

一次用户解释或追问使用一次CHAT额度；任务自动重试不重复扣减。用户明确重新生成是新业务请求，会再使用一次额度。没有新增EXPLANATION额度类型，不调用识别Worker。

## Prompt、结构与长期上下文

首轮固定 formula-explanation-v1，追问固定 formula-followup-v1。未知版本在调用前拒绝，不退回普通模板。首轮只使用固定公式和当前请求，重新生成不携带旧追问。

成功结果包含summary、symbols、conditions、steps、examples、warnings和schemaVersion；允许不适用区块为空，不编造推导。限制summary 1200字符、符号12项、条件/警告各8项、步骤6项、例子2项；总JSON不超过16000字符。沿用2048输出tokens与60秒期限，没有声称足够覆盖任意复杂公式。

基础解释独立于最近100条消息读取，追问Prompt保留该完整成功问答，再按预算纳入近期成功问答；失败、停止、破损历史不参与。当前问题单独追加一次。公式后续编辑不会替换固定版本。

结构生成期间只显示任务状态和心跳，不把半份JSON当成可用解释。完整流、finish_reason及结构校验通过后，结构JSON、确定性兼容文本、业务完成、调用提交标记、revision和队列确认共同提交。合法重试清空旧片段，失效Worker不能提交。

上游完整返回但JSON无效时，调用可记SUCCEEDED而业务FAILED，并记录INVALID_OUTPUT/resultDiscardedAt；它不表示数学正确或已免计费。缺失用量仍为UNKNOWN，Mock不虚构token及供应商费用。

## 协议与兼容边界

GET、SSE、停止响应保持v2完整快照，不新增增量事件或第二套连接。baseExplanation与结构字段进入同一RepeatableRead快照及客户端revision比较；基础解释一旦成功不可回退或替换。

旧客户端可忽略新增字段并展示兼容文本；新客户端不渲染未验证JSON。失败/停止继续保留已有业务终态语义。

部署兼容不等于任意新旧Worker混跑：旧Worker不理解结构化任务。未来发布须先部署兼容迁移、更新/排空旧Worker，再开放新解释入口；禁止让旧Worker消费新解释任务。本轮未执行部署。

## 限制与回滚

- 没有真实DeepSeek内容质量/耗时验收；JSON合法不等于数学正确。空、截断或不合格回答明确失败，不自动再次付费修复。
- 视口和触控验证为Windows Chromium模拟，不冒充真实iPhone/Safari；未做生产规模容量或负载承诺。
- 旧文本历史不自动升级成结构化解释。仅账号持久化公式使用新入口，不新增游客永久解释库。
- 回滚应用时保留加法数据库字段及解释数据。不要删历史、回滚到无法处理新任务的旧Worker，或在队列仍有新任务时撤回兼容代码。
- 发布仅从安全main分支执行正常推送、PR和保留历史合并；不force push、不生产迁移、不自动部署、不进入R20。
