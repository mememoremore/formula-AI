# R4 首页重构与验收说明

基线：R3 `829f7ad`；工作分支：`refactor/r4-home`。本轮只改首页及直接依赖，不进入 R5。

## 1. 设计与职责

按 Mobile First 顺序，先验证 320/390/430px 的完整产品 UI 和状态，再验证 768/1440px。沿用 R2 浅紫、纸页、边框、圆角、字体及留白，不新增全局 Token，也不更换框架。

首页插画从绝对定位、负 right/负边距改为正常网格中的图片。文字列和图片列均使用 minmax(0, …)，图片宽度不超过所在列；没有全局裁切或把整页公式缩小。识别与上传是两个独立的大触控入口，保留相机 source=camera 与相册语义。

首页卡片取消说明的两行截断，标题/正文完整换行。真实公式另放在可聚焦、可横向滚动的区域；原图/示例缩略图继续保留。公式区域在链接外，避免键盘阅读数学内容时误触跳转。首页品牌、头像、主入口和底部导航的触控高度至少 44px，固定导航仍由 R3 管理。

| 模块                       | 职责                                                                             |
| -------------------------- | -------------------------------------------------------------------------------- |
| app/pages/index.vue        | 等待共享会话、组合 Hero/记录/状态；不直接编排接口                                |
| HomeHero.vue               | 纯展示，接收两个目标地址，无请求或全局状态                                       |
| useHomeOverview.ts         | 复用传入的 workspace，会话/最近记录/演示/导航目标的首页编排                      |
| app/utils/home-overview.ts | 两组列表的部分失败隔离、取消检查、游客会话恢复规则                               |
| RecentEntryCard.vue        | 记录链接、缩略图、完整文字及数学预览；仓库正式页面中仅首页使用                   |
| AppBrand.vue               | 新增可选 accountUser；首页传入已读取用户，避免品牌再发会话请求；原调用不传时兼容 |

此前 Session 和记录失败共用按钮，但按钮只刷新 home-recent；现已分开。取数抽离时发现重复会话读取会使 SSR 状态变化，已通过复用同一 workspace 和向品牌传入用户消除，不用条件补丁隐藏水合警告。

## 2. 实际数据语义与缓存边界

- 账号公式来自现有 `/api/account/library`，按服务端 createdAt/id 降序，首页展示首条；展示最新公式版本，但不代表最后编辑时间，也不是正在运行的识别任务。
- 账号对话来自现有 `/api/account/conversations`，按对话创建时间降序，展示首条；因此标记“最近创建的对话”，不冒称最近活跃。
- 接口原本返回第一页，未新增 limit 参数或改变服务端协议。首页只取第一条；读取两页现有列表的开销保留给后续确有需要的优化。
- 游客公式仍使用既有数组首项。预置示例与本次演示识别分别标注，不冒充真实识别记录。
- 游客聊天没有活动时间戳，按现有存储顺序选可恢复的非空会话，标记“继续本机对话”。旧版本会话传递原 demoVersionId，孤立版本不错误降级成自由提问。
- 保留 **home-recent** 缓存键，兼容现有登录、退出和公式变更失效名单；没有重构全站缓存，也没有引入 Pinia。
- ownerId 变化会刷新首页请求。结果带 ownerId，展示前匹配当前身份；传递 AbortSignal 并在提交结果前检查取消。Session 待确认/失败时不展示记录；身份切换不会显示另一账号或游客混合数据。

## 3. 状态与重试

| 场景             | 表现与动作                                                               |
| ---------------- | ------------------------------------------------------------------------ |
| Session 失败     | 单独提示账号未确认；不降级示例；“重新连接账号”刷新 Session               |
| Session/记录加载 | 保留识别入口，记录区域显示骨架与 aria-busy；避免空状态闪现               |
| 一组记录失败     | 成功记录仍能打开，失败组明确提示                                         |
| 两组记录失败     | 显示记录错误，仍保留主入口；不伪装为空记录                               |
| 重试记录         | 显式重读两个现有列表，成功后清除失败状态；保留一个缓存键以兼容原失效规则 |
| 账号空记录       | 显示首条公式引导和识别入口；有对话但无公式时仍保留对话                   |
| 游客             | 示例、继续本机对话及真实账号边界清楚                                     |

记录请求无自动重试，每个请求 10 秒超时。Session 使用原有请求配置。本轮没有添加 Worker 或付费模型重试。

## 5. 安全测试方式

沿用 R1/R2 空 dotenv、清洁环境的 `preview:design`，未连接开发数据库、队列、对象存储、Python 或付费模型。

测试层 `home-fixtures.ts` 声明账号有记录、空记录、两种部分失败、全部记录失败、Session 失败、延迟、其他账号及长内容。隔离浏览器的 r4-home Cookie 选择场景，SSR 与客户端读取同一替身。此 Cookie 不是认证凭据，不创建真实账号。场景接口未声明的 API 直接拒绝，避免误触业务请求。

`/__home` 只在显式预览层装配真实首页，提供布局对比和刷新测试会话按钮；用于实际验证刷新、加载、身份切换。`/__home-before` 与 HomeBeforeCard 是 R3 基线对照。正常生产构建不加载这些页面、测试按钮和替身。

执行入口：

```powershell
npm run check:assets
npm run typecheck
npm run typecheck:design
npm run test:unit
npm run check:build
npm run preview:design
playwright-cli -s=formula-r4 open http://127.0.0.1:3200/
playwright-cli -s=formula-r4 run-code --filename=tests/design-preview/check-home-browser.js
```

先完成类型检查，再启动稳定预览进行浏览器验收，避免生成目录热更新干扰。CLI 的 `### Error` 必须判为失败，不能只看 shell 退出码。故障场景会返回预期 503；资源错误不代表 Vue 脚本或水合错误。

## 7. 未完成与风险

- 登录态、错误和身份切换均为受控测试替身；真实 Better Auth 登录、真实数据库归属、模型、SSE、文件上传/导出未在 R4 联调，不能据此声称通过。
- 未做真机软键盘、Safari、动态工具栏或完整 WCAG 认证。手机 CSS 视口结果不能替代真机。
- 游客缺少活动时间戳，所以继续会话的选择没有改成“最近活跃排序”；如需此语义，应在后续产品确认后再调整数据格式。
- 公式库原有小屏装饰溢出仍归 R5，本轮未顺手修复。
- 首页保留现有列表接口和缓存键；全站缓存失效统一仍归 R11。

## 8. 版本与后续

本轮使用独立本地提交，最终 Commit 在交付会话列出。回滚使用经确认的 `git revert <R4提交>`，保留 R3 历史，不 reset --hard、不清理用户资源，不推送远程。

R5 同样先验收 320/390/430px，修正公式库装饰边界，再梳理分类、筛选、空/错/加载和分页。保留链接上下文及收藏契约，桌面 workspace 应在手机稳定后逐步采用，不照搬首页的布局或缓存规则。
