# 识别结果核对与修改对照（待确认设计）

日期：2026-11-01。状态：设计草案，尚未实施；本轮仅执行 CI 与 README 收尾。

## 目标与推荐方案

帮助用户确认“识别出来的公式是否与图片一致”，并看清修订内容。优先移动端，复用私有原图、LaTeX 编辑器及不可变版本，不引入额外识别模型或改写原始识别结果。

方案比较：独立核对页流程清楚，但重复详情与编辑能力；仅增加核对按钮成本低，但没有提供核对依据；推荐在详情与现有编辑弹窗中增加对照模式，保持上下文并复用现有保存与冲突处理。

## 手机页面与操作

识别完成进入详情后，在公式标题旁显示“待核对”。原图与渲染公式作为一个核对区：默认上下排列，原图可展开与缩放；用户也可收起原图继续阅读。窄屏不强制左右分栏，桌面可并列。

主要操作为“修改公式”和“确认当前版本已核对”。核对是用户确认，不表示系统证明数学正确。AI 与导出仍可使用，待核对时给出简短提醒，不强制用户走完整流程。

修改界面保留原图参考，输入下方实时显示修订预览；展开“查看修改”后上下显示“修改前”和“修改后”，同时提供 LaTeX 增删对照。第一版用源码标记差异，不宣称能判断数学等价，也不尝试把不同渲染公式的字符位置强行对齐。

底部为“取消”和“保存新版本”。保存有变化的内容才生成版本，原始识别永久保留。未保存离开沿用应用内确认弹窗；保存结果不明确时复用原请求，不能盲目创建第二个版本。

## 核对状态与版本

核对记录独立于不可变 FormulaVersion，拟新增版本核对表，保存 ownerId、formulaVersionId、reviewedAt；账号与版本使用联合归属约束，防止跨账号标记。唯一约束保证同账号同版本的重复确认幂等。可撤销当前版本的核对，撤销不删除公式或版本。

旧识别公式默认待核对；核对 v1 后，编辑得到的 v2 默认待核对，v1 的核对记录继续保留。改标题与分类不改变内容版本或核对状态。手动创建公式显示“手动输入”，可查看首版和修订对照，但不标为“识别待核对”。

数据库迁移为新增表和索引，不删除或回填已有公式内容。实现前需确认 Schema/API 设计，并在独立测试库验证兼容旧数据。

## 异常与并发

原图失效时显示重试与无法读取提示，不用空白图冒充加载完成。仍可查看、编辑公式；暂时禁用“确认已核对”，待原图成功加载后再确认。

确认核对时带当前版本标识。若其他窗口已经保存更新版本，返回冲突并提示读取最新版，不把旧版本的核对套到新版本。详情读取核对状态与当前版本需一致；账号退出或切换后清理私有状态。

## 首版边界

不做自动框选错误字符、AI 置信度、语义等价判定、整页多公式或自动批量修订。长源码差异设置长度上限与降级展示，避免手机页面卡顿。无需引入付费外部服务。

## 验收场景

1. 原始识别图片、源码与 v1 在修订后仍可读取。
2. 原样保存不产生空版本；源码增删能在修改对照中查看。
3. v1 核对后创建 v2，v2 显示待核对；改标题不会清除当前内容的核对状态。
4. 两窗口并发编辑或核对旧版本时有明确冲突，不产生错误状态或重复版本。
5. 他人账号无法读图、修改或标记核对，未登录请求被拒绝。
6. 手机 320、390、430px 下原图可查看、长公式独立滚动、操作可触达；真实手机补验键盘、缩放和安全区。
